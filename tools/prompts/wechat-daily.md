写作规则：

1. 先统计消息范围、消息类型、图片、文件、视频、URL 和导出时间。
2. 按工程主题组织“当天主线”，不要按流水账排序。
3. 每条主线保留讨论演进、关键分歧或决策、工程含义，以及带时间和发言人昵称的短原文。
4. 模型对比、风险清单、成本观察和方案取舍使用表格。
5. 区分群友观点、传闻和已核实事实；不要把主观体验写成客观结论。
6. 重要链接记录标题、分享者/时间和价值。
7. 报告已保存文件和图片，并列出缺失媒体的 MD5 与补齐方法。
8. 绝不复制 API key、token、密码或其他凭据。若聊天中出现凭据，只说明需要撤销。
9. 表达直接、紧凑、面向工程判断；不要空泛鼓励。
10. 只修改目标日报文件，不要修改其他文件，不要执行 git 操作。
