# 根据文档生成规则

## 任务要求

1. 你的任务是收集关于该项目的特定的信息，并创建或编辑关于该项目的规则文件
2. 使用相应的工具获取有关项目的信息
3. 只关注你通过阅读文件发现的、项目特定的、非显而易见的信息
4. 你必须以用户代码库的基本事实为依据，禁止根据已有经验幻想输出

## 创建或编辑规则

### 基本要求

1. 规则应该存储在 `.comate/rules` 目录中
2. 规则文件必须使用 `.mdr` 扩展名（例如：`my-rule.mdr`）
3. 元数据存储在 frontmatter 中，控制规则的使用方式，必须格式正确
4. 规则文件中必须包含元数据属性
5. 规则使用 Markdown 格式
6. 要在规则中引用文件，使用格式：`[filename.ext](mdr:filename.ext)`，其中路径相对于工作区根目录

### 规则元数据属性

| 属性名        | 类型       | 说明                                                            |
| ------------- | ---------- | --------------------------------------------------------------- |
| `alwaysApply` | true/false | 如果为 true，将应用于每个请求                                   |
| `description` | string     | 规则描述                                                        |
| `globs`       | string     | 以逗号分隔的 gitignore 样式模式列表，控制此规则将应用于哪些文件 |

> **注意：** 通常只会设置这些类型中的一种，但同时拥有 globs 和 description 也是有效的。

## 规则示例

### 示例 1：始终应用的项目结构规则

这个规则会在所有请求中自动应用，用于说明项目结构：

```markdown
---
alwaysApply: true
---

# 项目结构指南

主入口点是 [index.js](mdr:index.js)，它从 [config.js](mdr:config.js) 加载配置
```

### 示例 2：仅应用于 TypeScript 文件的规则

这个规则只会应用于 TypeScript 和 TypeScript React 文件：

```markdown
---
globs: *.ts,*.tsx
---

始终使用分号
```

### 示例 3：手动应用的规则

这个规则不会自动应用，需要用户手动应用：

```markdown
---
alwaysApply: false
---

关于特定任务必须遵守的规则
```

## 使用说明

- 使用这些说明生成新规则或修改现有规则
- 规则文件中必须包含元数据属性
- 规则必须以用户代码库的基本事实为依据，禁止根据已有经验幻想输出
- 规则填加需要遵循非显而易见的原则，删除显而易见的规则信息
- 如有对话历史，请参考对话历史记录来理解应该生成的规则
- 合理使用 `alwaysApply`、`description` 和 `globs` 来控制规则的应用范围
- 如果用户选择了文件或是文件夹，请只给用户所选内容生成规则
- 如果用户没有任何选择，则为整个代码库生成规则

## 需要添加的内容

- 无法从标准实践猜出的信息
- 项目特定的，非通用的知识
- 通过阅读代码，配置文件才能发现的内容
- 不遵循会导致错误的关键信息

## 最佳实践

- 为频繁使用的项目约定创建 `alwaysApply: true` 规则
- 使用 `globs` 模式为特定类型的文件定义规则
- 保持规则简洁明了，便于理解和高效开发
- 规则文件最长不要超过200行
- 定期审查和更新规则以反映项目的演变
