# 快速参考：如流消息过滤功能使用指南

## 🎯 功能说明

该功能允许 Agent 只将最终结论推送到如流，而将中间排查过程保留在 TestOne 平台，让用户在如流中看到精简的回复。

## 📝 模型输出格式要求

当 Agent (Ducc) 完成排查并准备给出最终结论时，必须按以下格式输出：

```
好的，我来帮你排查这个问题...

（中间排查过程，包括数据库查询、日志分析等）

----回复----
🔍 问题分析

（最终结论内容，这部分会推送到如流）
```

## 🔑 关键分隔符

- **分隔符**: `----回复----`
- **作用**: 分隔中间过程和最终结论
- **位置**: 必须单独占一行
- **效果**: 分隔符之前的内容只在 TestOne 显示，之后的内容推送到如流

## ⚙️ 技术实现

### 关键代码位置

1. **CLAUDE.md**: 第 53-73 行 - 定义了输出格式规范
2. **task.py**: 第 80-195 行 - 实现了消息过滤逻辑

### 消息处理流程

```
AssistantMessage 收到文本
    ↓
累积到 _accumulated_text
    ↓
检测是否包含 "----回复----"
    ↓
是 → 分割内容
    ├─ 前半部分 → to_infoflow=False (只在 TestOne 显示)
    └─ 后半部分 → to_infoflow=True (推送到如流)
    ↓
否 → 继续累积，to_infoflow=False (实时显示在 TestOne)
    ↓
收到 ResultMessage
    ↓
检查是否已推送到如流
    ↓
否 → 触发兜底机制
    └─ 推送累积的文本或 ResultMessage.result 到如流
```

## 🛡️ 兜底机制

如果模型忘记使用 `----回复----` 分隔符，系统会自动：
1. 等待所有消息处理完成
2. 在 `ResultMessage` 阶段检测是否有内容推送到如流
3. 如果没有，将所有累积的文本作为最终结论推送到如流
4. 确保用户至少能收到一条回复

## ⚠️ 注意事项

1. **分隔符格式**: 必须是 `----回复----`，前后不能有空格，必须单独占一行
2. **内容完整性**: 分隔符之后的内容应该是完整的、可独立理解的结论
3. **保持简洁**: 如流端的回复应该简洁明了，控制在合理长度内
4. **Emoji 使用**: 可以适当使用 emoji 增加亲和力，但不要过度

## 📞 问题排查

### Q: 如流没有收到任何消息？
A: 检查日志，看是否触发了兜底机制。如果兜底机制也没有触发，可能是消息处理流程出现异常。

### Q: 如流收到了太多中间过程信息？
A: 检查 CLAUDE.md 中的提示词是否被正确加载，确认模型是否理解了分隔符规则。

### Q: 分隔符没有被识别？
A: 确认分隔符格式是否正确（`----回复----`），是否单独占一行，前后是否有多余字符。
