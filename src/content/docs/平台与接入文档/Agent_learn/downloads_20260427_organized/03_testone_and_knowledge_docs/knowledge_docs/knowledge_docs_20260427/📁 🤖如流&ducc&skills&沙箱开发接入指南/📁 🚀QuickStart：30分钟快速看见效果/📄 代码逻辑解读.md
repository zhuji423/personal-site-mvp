## 一、整体架构概览
这是一个基于 **Flask + Claude Code (ducc) + TestOne** 的 AI Agent 服务，核心流程如下：

```
HTTP请求 → Flask接口 → 异步线程 → DuccDemoAgent → Claude Code执行 → 流式推送结果 → 回调TestOne
```
整体分为 4 个模块：

|模块|内容|
|-|-|
|**Web服务层**|Flask 提供 `/aiAgent/execute` 接口，异步处理任务|
|**Agent执行层**|`DuccDemoAgent` 封装核心业务逻辑|
|**工作空间管理**|`prepare_workspace` 按用户/群组隔离工作目录|
|**结果回调层**|`call_and_callback` 执行完毕后通知 TestOne|

---

## 二、核心类：DuccDemoAgent
继承自 `BaseDuccAgent`，是整个系统的核心执行单元。

### 2.1 初始化
```
def __init__(self, param: TaskParameter):
    workspace = prepare_workspace(param)         # 准备隔离工作空间
    super().__init__(param, DUCC_BIN_PATH, workspace)
    self.ducc_util = DuccUtil(DUCC_BIN_PATH, workspace, CC_PROJECTS_DIR)
```
初始化时会调用 `prepare_workspace` 准备工作空间，传入 `ducc` 可执行文件路径和工作目录。

---

### 2.2 execute() — 主入口
```
用户Query
   ↓
是否 "/clear"?
  ├─ 是 → 清除记忆，推送提示
  └─ 否 → asyncio.run(call_ducc())
   ↓
返回 AgentResult(SUCCESS)
```
* 支持 `/clear` 指令：清除当前会话记忆，开始全新对话
* 其他输入一律走 `call_ducc()` 处理

---

### 2.3 call_ducc() — Claude Code调用核心
```
获取用户Query
    ↓
从记忆中获取 session_id（支持多轮对话）
    ↓
构建 ClaudeAgentOptions（配置权限、工具、hooks）
    ↓
拼接 Prompt（注入用户名、群ID等上下文）
    ↓
ClaudeSDKClient 异步执行
    ↓
启动一个10s的定时器，定时检查任务在云端的状态，如果超时或者取消，则自动中断本地claude的执行
    ↓
遍历响应消息流：
  ├─ SystemMessage(init)  → 存储 session_id 到记忆
  ├─ 所有消息            → parse_cc_msg_and_push_to_testone（流式推送）
  └─ ResultMessage(定时任务) → 发送如流通知给负责人
```
**关键配置项：**

|配置|值|说明|
|-|-|-|
|`permission_mode`|`acceptEdits`|自动接受文件编辑操作|
|`allowed_tools`|Read/Write/Edit/Grep/Glob/Bash/Skill|限制可用工具|
|`resume`|mem_session_id|续接历史会话，实现多轮对话|
|`setting_sources`|user/project|加载用户+项目级配置|

**Hook 机制：**

* `PreToolUse[Bash]`：执行 Bash 命令前调用 `validate_bash_command` 校验，超时 180s
* `PostToolUse`：每次工具调用后通过 `log_tool_use` 记录日志

---

### 2.4 多轮对话支持
通过 `session_id` 实现跨次对话记忆：

```
第一次对话 → init消息携带 session_id → 存入 aiworker_memory
后续对话   → 从 memory 取出 session_id → ClaudeSDKClient.resume=session_id → 续接上下文
```

## 三、工作空间管理：prepare_workspace()
这是**多租户隔离**的核心实现，按用户/群组区分工作目录。

### 3.1 工作空间优先级
```
1. 从记忆中取已有 workspace（路径存在则复用）
2. 如果是如流群聊 → workspace = BASE_WORKSPACE/{群ID}
3. 如果是单聊用户 → workspace = BASE_WORKSPACE/{用户名}
4. 其他场景(TestOne) → workspace = BASE_WORKSPACE/{taskIndex}
```
### 3.2 权限配置（RBAC）
通过 `group_conf` 和 `user_conf` 实现不同用户/群具备不同的能力：

**群组配置示例：**

|群组|CLAUDE.md|可用技能|
|-|-|-|
|9295350（内部群）|CLAUDE.md（完整权限）|file-upload、icafe-helper、infoflow-helper、testone-faq|
|default|CLAUDE-DEFAULT.md（受限）|file-upload、testone-faq|

**用户配置示例：**

|用户|CLAUDE.md|可用技能|
|-|-|-|
|guyouda|CLAUDE.md（完整权限）|file-upload、icafe-helper、infoflow-helper、testone-faq|
|zhangtao77|CLAUDE.md|file-upload、icafe-helper、testone-faq|
|default|CLAUDE-DEFAULT.md|file-upload、testone-faq|

### 3.3 工作空间初始化流程（首次创建）
```
创建 workspace/.claude 目录
    ↓
拷贝 CLAUDE.md（对应权限的Prompt配置）
    ↓
拷贝 MEMORY.md（长期记忆）
    ↓
拷贝对应的 Skills 目录（.claude/skills/）
    ↓
拷贝 setting.json（Claude Code配置）
    ↓
执行 init-workspace.sh（初始化Python虚拟环境，用户间隔离）
    ↓
记忆中存储 workspace 路径（下次直接复用）
```
> **设计意图**：通过工作空间隔离，同一个 Agent 服务可以为不同用户/群提供差异化能力，避免权限越界。

## 四、Web服务层
### 接口：POST /aiAgent/execute
```
@app.route("/aiAgent/execute", methods=['POST'])
def execute():
    param_dict = request.json
    thread = threading.Thread(target=call_and_callback, args=(param_dict,))
    thread.start()
    return jsonify({"code": 0, "msg": "success", "thirdTaskId": log_id})
```
**特点：**

* 立即返回（异步），避免阻塞
* 实际执行在独立线程中完成
* 返回 `thirdTaskId` 供 TestOne 追踪

---

### call_and_callback() — 执行+回调
```
解析 TaskParameter
    ↓
初始化运行环境（TESTONE_USERNAME/TOKEN 注入环境变量）
    ↓
DuccDemoAgent.execute()
    ↓（成功或失败）
POST 回调 TestOne /aiqa/task/callback
```
* 异常时会通过 `push_result_stream_data` 推送错误信息给用户（包括如流）
* 无论成功失败都会回调 TestOne，保证任务状态更新

## 五、定时任务支持
当 `operate_type == OperateTypeEnum.AIWORKER_CRONJOB` 时，Claude 执行完毕后会：

1. 生成 Markdown 格式的结果通知
2. 通过如流 App 发送给对应负责人（当前配置发给 operator 本人）
3. 支持扩展为发送群聊通知（代码中有注释示例）

## 七、完整数据流
```
用户在如流/TestOne发起请求
    ↓
TestOne 调用 POST /aiAgent/execute
    ↓
Flask 启动独立线程（立即返回）
    ↓
load_task_parameter 解析任务参数
    ↓
prepare_workspace 准备隔离工作空间（含CLAUDE.md/MEMORY/Skills）
    ↓
ClaudeSDKClient 调用 Claude Code (ducc)
    ↓
ducc 在隔离工作空间内使用 Read/Write/Bash/Skill 等工具完成任务
    ↓
响应流式返回 → parse_cc_msg_and_push_to_testone 实时推送给用户
    ↓
session_id 存入记忆（支持多轮对话）
    ↓
POST 回调 TestOne /aiqa/task/callback 更新任务状态
```

## 八、部署注意事项
1. **ducc路径**：修改 `DUCC_BIN_PATH` 为实际的 `which ducc` 输出路径
2. **CC项目目录**：修改 `CC_PROJECTS_DIR` 为 `~/.claude/projects` 实际路径
3. **账号配置**：可通过环境变量 `BAIDU_CC_*` 和 `ANTHROPIC_*` 配置团队公共账号
4. **端口**：默认 `8888`，生产环境建议使用 gunicorn/uwsgi 替代 Flask 内置服务器
5. **resources目录**：需包含 `CLAUDE.md`、`CLAUDE-DEFAULT.md`、`MEMORY.md`、`setting.json`、`init-workspace.sh` 以及 `skills/` 各技能目录
