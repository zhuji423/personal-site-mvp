多轮对话怎么复用之前的上下文继续沟通

# 1、背景
自己直接命令行使用ducc的时候，只要不新开会话，在同一个会话里面继续聊，之前的沟通内容的上下文记忆全都有，ducc会自动使用之前的上下文信息。

但是如果基于SDK去调用ducc的时候，如果不显式指定会话ID(sessionId)，那么每次都是自动开一个新的会话，所以每次开局就失忆，不记得之前的所有信息了。

# 2、思路
[流程图]
## 2.1、持久化sessionId
要想不断片，核心在于得知道每次API调起的时候，之前是否聊过，对应的会话ID是什么，得持久化记录下来

* 本地：直接自己在本地文件基于json的形式记录一下会话ID
* 数据库：自己存储到数据库里面
* 使用平台默认的记忆能力

## 2.2、session管理的维度
建议区分使用场景：

* 针对如流数字员单聊沟通的场景，按照人的维度记录
* 针对如流数字员群聊沟通的场景，按照群聊ID的维度记录，这样一个群里大家沟通的信息AI都能知道，方便更好的回答

## 2.3、上下文爆炸
**一个群一个session或者一个人一个session，这种做法，时间久了，会上下文爆炸影响效果？**

* 可以适当优化下，比如叠加时间因子进来
    * 一个人一天一个会话
    * 一个群一天一个会话


**一天沟通的内容太多了也会影响效果？**

* 可以提前检测下会话内容的大小，太大了的话，自动启用新会话，否则复用

**以上还不够？**

* 自己结合用户名+群聊ID+本轮的问题+历史session和问题等数据，综合决定开一个新会话，还是复用历史的某个会话
