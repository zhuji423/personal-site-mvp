1.项目组织结构

如下是一个 GDP 项目的组织结构。

1. 使用 gdp new 命令([http://gdp.baidu-int.com/gdp3/docs/quickstart/gdp/](http://gdp.baidu-int.com/gdp3/docs/quickstart/gdp/))可以创建出
2. 该组织结构并非强制，仅供参考，可根据业务实际需求需求和规范，进行调整



## 1. 目录结构
### 1.1 整体
```
.
├── bin            // 存放启动脚本，编译输出的二进制文件
├── bootstrap      // 应用初始化相关代码
├── cmd            // 其他 Go CLI 程序代码，如定时任务程序、临时处理数据的程序
├── conf           // 配置文件，线下测试开发
├── conf_online    // 配置文件，线上
├── document       // 设计文档存放目录，可选
├── servers        // 将一个应用的所有的 server 都放在此目录下
│   ├── start.go   // 负责所有 server 的启动管理功能
│   ├── adminserver  // 管理类功能的 server，也是一个 HTTP Server，监控指标等信息也是通过这个 server 对外输出
│   ├── httpserver   // HTTP Server   的相关代码(Server创建、路由注册、协议专属的控制器代码)
│   ├── nsheadserver // NSHEAD Server 的相关代码(Server创建、路由注册、协议专属的控制器代码)
│   └── pbserver     // pbrpc Server 的相关代码(Server创建、路由注册、协议专属的控制器代码)
├── model          // 业务模型层代码
├── library        // 模块自己的公共基础库，没有 RPC 调用的可以放在这里
├── script         // 其他相关脚本，如 php、python、shell 脚本
├── data           // 数据目录，线下测试开发
├── data_online    // 数据目录，线上
├── noahdes        // 配置派生的目录，可选
├── log            // 日志输出目录，不同类型的日志分别放在不同的子目录
├── webroot        // 当对外提供 HTTP 服务时，此目录存放 css、js 等资源文件
├── 
├── ⬇ ️下面是单个文件，都需要提交到代码库
├── main.go        // 当前应用的主入口文件
├── ci.yml
├── Makefile
├── README.md
├── go.mod         // module 描述文件，包括依赖的版本信息
└── go.sum         // 依赖模块的签名信息，不可缺少
```

### 1.2 conf-配置文件目录
```
├── conf
│   ├── app.toml               // 应用主配置文件
│   ├── logit                  // 日志的配置
│   │   ├── ral-worker.toml   // 使用 servicer 访问下游的行为日志配置
│   │   ├── ral.toml          // servicer 管理的日志
│   │   └── service.toml      // Server access log 配置
│   ├── port.conf
│   └── servicer               // 下游服务配置
        └── gdp_site.toml
```



### 1.3 data-数据文件目录
```
├── data
│   ├── README.md
│   ├── dynamic_dict      // 动态词典文件目录,如使用 noahdt、mis配送的词典文件
│   │   └── README.md
│   ├── static_dict       // 静态词典文件目录,不会更新、文件尺寸较小，直接提交到代码库的词典文件
│   │   └── README.md
│   └── var               // 程序产生的临时文件
│       └── README.md
```



### 1.4 hestia-热重启子模块目录
在 CNAP 上并不支持该功能，所以 gdp new 创建的新项目已移除功能，配置不再需要。

```
├── hestia                         // 若使用热重启功能，需要将 baidu/gdp/hestia 部署在此目录下
│   ├── README.md
│   ├── conf                      // baidu/gdp/hestia 模块所需要的配置文件
│   │   └── hestia.toml          // 进程信息、监听端口信息等
│   └── var
│       └── app_version.txt       // 主模块的应用版本信息，主模块每次编译产出都会更新。hestia 检测到该文件变化后将触发 Hot Reload。
```
详见：[热重启功能](https://wiki2ku.baidu-int.com/pubapi/urlmap?id=1370968292)




### 1.5 httpserver-HTTP Server 目录
```
├── httpserver            // 所有 HTTP Server 所独有的逻辑全部放在这个目录下
│   ├── controller       // 控制器代码
│   │   ├── hello.go
│   │   └── sum.go
│   ├── middleware       // 中间件
│   │   └── print.go
│   ├── router.go        // 路由注册
│   └── server.go        // Server 初始化
```
原则：

1. 各种 server 所特有的 server 初始化、路由注册、协议专属的控制器代码(处理输入和输出)都放在一起。
2. 和 Server 具体协议无关的业务模型层代码放入到 顶层的 model 目录。
3. 所有协议的 server 都保持这一原则。（如下 nsheadserver）

### 1.6 nsheadserver-NSHEAD Server 目录
