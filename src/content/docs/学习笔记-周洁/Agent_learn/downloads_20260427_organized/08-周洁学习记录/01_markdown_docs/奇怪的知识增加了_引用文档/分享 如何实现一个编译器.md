### 著名的编译器工程
 GCC：GCC (GNU Compiler Collection) 是一套广泛使用的自由软件编译器,由 GNU 计划开发和维护。它支持多种编程语言,包括 C、C++、Objective-C、Fortran、Ada、Go 和 D 等。

他的架构就是最经典的编译器架构：

clang/LLVM：GCC非常伟大，但是多年的发展导致GCC的维护变成了一种手艺传承，类似window。而clang和LLVM作为后来者，自然在模化块，工程复杂度上有所作为。

LLVM 最初是美国伊利诺伊大学的一个研究项目。Clang 是前端，LLVM 是后端。LLVM 定义了一个基于单一静态赋值（SSA）形式的中间表示（IR）。许多编译优化因此更容易在 IR 上执行。还可以添加 LLVM IR pass 来添加自定义优化步骤。



你可以将LLVM看做一个超级大的编译工具库，几乎你能想到的所有编译工作他都有实现。现代的编程语言几乎都基于LLVM。

## 词法分析（scanner 实现）
词法分析的作用就是将源代码(也就是字符流) 转化为Token流。cheng

词法分析有许多的成熟工具如lex，bison等。这些工具可以通过组合出复杂的正则解决词法分析，我们这里就用最简单的Scanner思路去实现。

### 分析
首先定义一个结构体Token:

```
pub struct Token {
    pub token_type: TokenType, 
    pub lexeme: String,
    pub literal: Option<LiteralValue>,
    pub line_number: usize,
}
```
这个Token结构体的各个字段具有以下作用:

1. `token_type`: 表示该词素的类型，比如关键字、标识符、常量等。这个信息将用于后续的语法分析。
2. `lexeme`: 表示该词素的原始字符串形式，即源代码中的实际文本内容。
3. `literal`: 表示该词素的字面量值，比如数字、字符串等。这个信息将用于后续的语义分析。
4. `line_number`: 表示该词素在源代码中的行号信息，用于报告错误位置等。

> literal: 如 var str = "hello",此时「"hello"」,就是一个有Literal的String Token

## 语法分析（parser实现）
我们现在已经把源代码转化为Token序列，现在需要把Token序列转换为AST(抽象语法树)

语法分析同样也有很多的方法，我们同样也选择最容易理解的**递归下降算法**去实现。

### 问题分析与前置知识
语法分析器的任务是判断单词流表示的输入程序在该语言中是否是一个有效的句子,那么如何去判断一段是否合法呢？



**核心的问题：语言的规律能否 『形式化』的表示?**

> 形式化是一种将问题或概念转换为可操作的数学或逻辑形式的过程,以便于分析、推理和验证。这种方法可以提高问题描述和求解的精确性和可靠性
![](/personal-site-mvp/img/doc-placeholder.svg "")
乔姆斯基谱系(Chomsky hierarchy)是由著名语言学家诺姆·乔姆斯基提出的一种语言类型的分类体系。它将形式语言分为四个层次,从最简单到最复杂依次为:

1. 正则语言(Regular Language)
2. 上下文无关语言(Context-Free Language)
3. 上下文有关语言(Context-Sensitive Language)
4. 无限制语言(Recursively Enumerable Language)

这个层次结构也被称为"乔姆斯基阶梯"或"乔姆斯基范式"。它反映了形式语言的表达能力和复杂性从低到高的变化。

具体来说:

1. 正则语言: 可以用有限自动机(DFA或NFA)来识别和描述的语言。比如绝大多数编程语言的关键字、标识符等。
2. 上下文无关语言: 可以用上下文无关文法(Context-Free Grammar)来描述的语言。比如编程语言的语法结构。
3. 上下文有关语言: 需要用上下文有关文法(Context-Sensitive Grammar)来描述的语言。这类语言的复杂程度高于上下文无关语言。
4. 无限制语言: 这是最复杂的语言类型,可以用图灵机来描述。基本上可以认为是任何可计算的语言。



举个例子：

好的,我来分别举几个乔姆斯基谱系中各层级的例子，复杂度依次递增:

1. 正则语言(Regular Language)示例:

    * 数字序列: `[0-9]+`
    * 电子邮件地址的本地部分: `[a-zA-Z0-9_]+`
    * URL 路径中的文件名: `[a-zA-Z0-9_-]+\.[a-zA-Z]+`

2. 上下文无关语言(Context-Free Language)示例:

    * 算术表达式
    * 编程语言的语法
    * 括号匹配的字符串: `(())`, `([{}])`

3. 上下文有关语言(Context-Sensitive Language)示例:

    * 变量声明时类型检查: `int x = 1; string y = "hello";`
    * 数组下标检查: `a[i] = x` 要求 `i` 在数组大小范围内
    * 指针操作的内存地址检查

4. 无限制语言(Recursively Enumerable Language)示例:

    * 图灵机可以识别的任何语言
    * 任何可计算问题都可以用图灵机来表示,因此这一层包含了所有可计算语言
    * 这一层的语言描述能力是图灵完备的,可以表示任何计算过程

需要注意的是,上下文有关语言和无限制语言的例子通常较为复杂,需要涉及具体的语义约束和计算模型。而正则语言和上下文无关语言则相对简单。



总得来说 乔姆斯基的理论是说语言是可以被形式化的分析的，当然这跟他本人其实是个哲学家有关，他的观点和维特根斯坦有异曲同工之处，但是落在实际上很少有语言能够完全形式化，数理化的表达。自然语言的形式化归纳这条路在上世纪就已经死了，让计算机理解自然语言现在是统计派的时代（机器学习，深度学习）。



幸运的是，程序语言的语法相比自然语言可以说非常简单，我们可以通过上下文无关语法(Context-Free Grammar，CFG)对类似moss这样的松散类型语言进行公理化，形式化的约定。

#### 
#### CFG
教科书定义：

CFG的形式化定义可以表示为一个四元组G=(V,T,P,S)，其中V是非终结符号的集合，T是终结符号的集合，P是产生式规则的集合，S是起始符号。产生式规则的形式可以表示为A→α，其中A∈V，α∈(V∪T)，即由非终结符号和/或终结符号组成的任意符号串。起始符号S是一个特殊的非终结符号，它表示整个语言的起点。如果一个符号串w∈(V∪T)*可以被分解为一系列的产生式规则，使得每个产生式规则中的非终结符号都可以被替换为相应的右部符号，那么我们称这个符号串w属于该CFG所定义的语言。 

#### BNF&EBNF
描述CFG的工具就是著名的BNF(巴科斯范式)和他的增强版(EBNF)。

具体可以看[https://zh.wikipedia.org/wiki/%E5%B7%B4%E7%A7%91%E6%96%AF%E8%8C%83%E5%BC%8F](https://zh.wikipedia.org/wiki/%E5%B7%B4%E7%A7%91%E6%96%AF%E8%8C%83%E5%BC%8F),内容繁杂，此处略过。

BNF的核心理念就是『递归』，认为任何的语句可以通过有限次的递归分析得到有意义的解。

#### 例子
让我们跳出数学的符号游戏，从我们程序员熟悉的场景去理解BNF我们举个例子，以最简单的表达式为例：

```
1 - (2 * 3) < 4 == false // true
```


这是一个我们非常熟悉的表达式(expression),这样一个表达式，他可以被直接看成一个值  true.

对于一个没有函数调用的表达式，我们可以归纳出

1. 字面量(Literals)：数字、字符串、布尔值和 nil。
2. 一元表达式(Unary expressions)：前缀 ! 进行逻辑非操作,以及 - 用于取负数。
3. 二元表达式(Binary expressions)：我们熟悉的中缀算术运算符(+, -, *, /)和逻辑运算符(==, !=, <, <=, >, >=)。
4. 括号（grouping）：一对 ( 和 ) 包围的表达式。



同时我们需要考虑到运算符的优先级，而moss语言中与和或的表达式and和or关键字，我们可以得到以下的文法表达：

```
// * 符号表示零次或多次重复 
expression     → equality (( "and" | "or" ) equality)* ;
equality       → comparison (( "==" | "!=" ) comparison)* ;
comparison     → term (( "<" | "<=" | ">" | ">=" ) term)* ;
term           → factor (( "+" | "-" ) factor)* ;
factor         → unary (( "*" | "/" ) unary)* ;
unary          → ( "-" | "!" ) unary | primary ;
primary        → literal | grouping ;
literal        → NUMBER | STRING | "true" | "false" | "nil" ;
grouping       → "(" expression ")" ;
```
这其实就是一个不那么『数学』，但是很实用的形式化描述，它严格的描述了moss语言中的算数表达式的语法规则。

通过这套文法规则我们可以很轻松的实现递归下降算法。而BNF形式化表示的精髓也就是递归的文法

> GNU项目的命名GUN NOT UNIX；经典的无穷递归冷笑话
值得注意的是这套规则是按照从上到下的优先级执行的，也就是

```
    // 处理流程
    // equality(== !=)
    // -> comparison(< <= > >=)
    // -> term(+ -)
    // -> factor(* /)
    // -> unary(- !)
    // -> primary( () primitive)
```


我们取一条规则 

```
expression     → equality (( "and" | "or" ) equality)* ;
```
解释一下：

1. `expression`：这是整个表达式的最顶层规则。一个表达式由下面定义的几种情况组成。
2. `equality`：这是表达式的下一层,表示"相等性"表达式。比如 `a == b`、`a != b` 等。
3. `(( "and" | "or" ) equality)*`：这部分是整个表达式的核心。它表示:

    * 零次或多次重复下面的模式:
        * 出现 `"and"` 或 `"or"` 操作符
        * 后跟一个 `equality` 表达式


也就是说,在 `expression` 中可以有零个或多个 `equality` 表达式,每个 `equality` 表达式前可以有一个 `"and"` 或 `"or"` 操作符。

这种语法描述允许表达式中包含多个逻辑操作符和逻辑表达式,比如:



```
a == b
a == b and c > d
a == b or c > d or d < e
```

```
    r1-->l3["term: 1+1"]
    r1-->op3["!="]
    r1-->r3["literal: 2"]

    l3-->l4(literal: 1)
    l3-->op4(+)
    l3-->r4(literal: 1)

    l2-->l5(literal:1)
    l2-->op5("-")
    l2-->r5("grouping:(2*3)")

    r5-->r6("expression: 2*3")

    r6-->l7("literal:2")
     r6-->op7("*")
      r6-->r7("literal:3")


```


到这里我们就能很清晰的看出所谓的BNF文法在代码中完善实现之后我们就能**把一个Token序列转化为一颗语法树**！



有了语法树之后不管是求值还是判断代码是否合法就变得有迹可循了。

总的来说,表达式侧重于计算和值的产生,而声明侧重于程序执行和状态的改变。它们是编程语言的基本构建块,表达式常用于构建更复杂的声明。理解两者之间的区别对于掌握编程语言的基础知识很重要。

### 代码设计


废话不多说，直接给出moss的形式化EBNF语法：

```
program ::= (expression ";")* EOF 

fauxDeclaration ::= classDecl | funDecl | varDecl | fauxStatement
classDecl ::= "class" IDENTIFIER ("extends" IDENTIFIER)? "{" ( member)*"}"
funDecl ::= "fun" function 
varDecl ::= "var" IDENTIFIER ("=" expression)? ";" 

fauxStatement ::= for| if | print | return | while | block 
import ::= "import" IDENTIFIER "from" STRING ";"
export ::= "export" IDENTIFIER ";"
for ::= "for" "(" expression? ";" (expression)? ";" (expression)? ")" expression
if ::= "if" "(" expression ")" expression ("else" expression)?
print ::= "print" expression ";"
return ::= "return" (expression)? ";"
while ::= "while" "(" expression ")" expression
block ::= "{" (expression ";")* "}"

expression ::= fauxDeclaration| assignment
assignment ::= ((call ".")? IDENTIFIER "=" assignment) | logic_or 
logic_or ::= logic_and ("or" logic_and)*
logic_and ::= equality ("and" equality)*
equality ::= comparison (("==" | "!=") comparison)* 
comparison ::= term ((">" | "<" | "<=" | ">=") term)*
term ::= factor (("+" | "-") factor)* 
factor ::= unary (("/" | "*") unary)*
array ::= "[" (elements ","?)? "]" 
object ::= "#{" (objmembers ","?)? "}"

unary ::= ("!" | "-") unary | call 
call ::= primary ("(" arguments? ")" | "." IDENTIFIER | "[" expression "]")* 
primary ::= "true" | "false" | "nil" | "none" | "this" | NUMBER | STRING | IDENTIFIER | "(" expression ")" | "super" "." IDENTIFIER | array | object


objmembers ::= objmember | objmember "," objmembers
objmember ::= (IDENTIFIER | STRING) ":" expression
elements ::= expression | expression "," elements
function ::= IDENTIFIER "(" parameters? ")" block 
parameters ::= IDENTIFIER ("," IDENTIFIER)* 
arguments ::= expression ("," expression)*
member ::= access* ("fun" function| varDecl)
access ::= "private" | "public" | "dynamic" | "static" | "override"
NUMBER ::= DIGIT+ ("." DIGIT+)?
STRING ::=  '@'? '"' ([^"\\] | "\\" | '\"' | '\n')* '"'
IDENTIFIER ::= ALPHA (ALPHA | DIGIT)*
ALPHA ::= [A-Za-z_]
DIGIT ::= [0-9]
```


当然，这个语法大量参考了js和ruby的形式化语法，并且做了相当程度的简化。毕竟这种递归式的推导想要完整且正确的写出来并非简单的事情:（。

写出这份形式化语法其实已经完成了parser的设计，因为很多杰出的大脑已经完成了通过EBNF直接生成AST的工作，这里介绍一种叫做YACC（yet another compiler-complier）的工具：

```
%{
#include <stdio.h>
#include <stdlib.h>

// AST 节点定义
struct ASTNode {
    int type;
    // 其他属性
};

// AST 构建函数
struct ASTNode* makeNode(int type) {
    // 实例化 AST 节点并返回
}
%}

%token IDENTIFIER NUMBER STRING
%start program

%%

program:
    program_items EOF { $$ = makeNode(PROGRAM); }
    ;

program_items:
    program_item
    | program_items program_item
    ;

program_item:
    expression ';' { $$ = $1; }
    ;

expression:
    declaration { $$ = $1; }
    | assignment { $$ = $1; }
    ;

declaration:
    class_decl { $$ = $1; }
    | fun_decl { $$ = $1; }
    | var_decl { $$ = $1; }
    ;

class_decl:
    'class' IDENTIFIER 'extends' IDENTIFIER '{' members '}' {
        $$ = makeNode(CLASS_DECL);
        // 设置类名、父类等属性
    }
    ;

fun_decl:
    'fun' function { $$ = makeNode(FUN_DECL); }
    ;

// 其他产生式规则...

%%

int main() {
    // 调用解析器,获取 AST 根节点
    struct ASTNode* root = yyparse();

    // 对 AST 进行进一步分析和处理
    // ...

    return 0;
}
```

### 递归下降算法


每个非终结符号对应于一个过程，该过程负责扫描此非终结符号对应的结构

程序执行从开始符号对应的过程开始

当扫描整个输入串时宣布分析成功完成

![](/personal-site-mvp/img/doc-placeholder.svg "")
为了更好的理解句法分析的递归下降算法实现，还是手写了一个版本。

[https://github.com/ericCui97/moss/blob/main/src/parser.rs](https://github.com/ericCui97/moss/blob/main/src/parser.rs)

可以自行查看。建议可以通过这个rs文件后半部分的单元测试debug，看一下执行流程就懂了，其实就是把EBNF表达逻辑抄了一遍。



以下用一段简单的moss代码的句法分析过程为例，帮助大家理解递归下降算法。

```
fun foo(a, b) {
    var add = a+b;
    if(a + b > 3){
    return a + b;
    }
    return a;
}
```
根据上面的 EBNF 定义,我们可以使用递归下降解析算法来解析这段 代码。下面是一步一步的解析过程:

1. `program ::= (expression ";")* EOF`

    * 首先解析 `expression`，因为 `program` 由一系列 `expression` 组成。

2. `expression ::= fauxDeclaration| assignment`

    * 在这里，我们遇到了一个 `funDecl`，它是 `fauxDeclaration` 的一种。

3. `funDecl ::= "fun" function`

    * 读取 `"fun"` 关键字,然后解析 `function`。

4. `function ::= IDENTIFIER "(" parameters? ")" block`

    * 解析函数名 `"foo"`。
    * 解析参数列表 `(a, b)`。
    * 解析函数体 `block`。

5. `block ::= "{" (expression ";")* "}"`

    * 读取左大括号 `{`。
    * 解析函数体内的表达式序列。

6. `expression ::= fauxDeclaration| assignment`

    * 遇到了一个 `varDecl`，它是 `fauxDeclaration` 的一种。

7. `varDecl ::= "var" IDENTIFIER ("=" expression)? ";"`

    * 读取 `"var"` 关键字。
    * 解析变量名 `"add"`。
    * 解析赋值表达式 `a + b`。
    * 读取终止分号 `;`。

8. `expression ::= fauxDeclaration| assignment`

    * 遇到了一个 `if` 语句,它是 `fauxStatement` 的一种。

9. `fauxStatement ::= for| if | print | return | while | block`

    * 读取 `"if"` 关键字。
    * 解析条件表达式 `a + b > 3`。
    * 解析 `if` 块内的表达式 `a + b`。
    * 解析 `else` 块内的表达式 `a`。

10. `expression ::= fauxDeclaration| assignment`

    * 遇到了一个 `return` 语句,它也是 `fauxStatement` 的一种。

11. `fauxStatement ::= for| if | print | return | while | block`

    * 读取 `"return"` 关键字。
    * 解析返回表达式 `a + b` 和 `a`。

## 代码执行
我们得到了AST之后，其实就已经可以做很多事情了：

1：markdown转化为真实的ui，有了AST之后就可以做简单的map直接渲染了。

2：类似babel的工具可以把高版本的js通过分析ast的方式转化为低版本的js，带来更好的兼容性

3：静态分析：现代IDE中的提示和实时飘红是通过静态分析AST实现的

。。。



但我们如果想要执行代码呢？

最直接也是最简单的思路就是直接把AST这颗树后序遍历，压到栈中依次，通过宿主语言（这里是rust）直接翻译执行。这种方法简单，但是效率很差。

想要了解这种方式实现，可以参考：[interpreter实现](https://github.com/ericCui97/moss/blob/main/src/interpreter.rs)



其实到这一步我们就走到了编译这件事情的难点上

### 更好的方法 栈与字节码


更好的方式是实现一个栈虚拟机，将AST先翻译成字节码，通过字节码和栈虚拟机，可以做到几千几万倍的性能提升。根本原因就是下面这张CSAPP中的图：



![](/personal-site-mvp/img/doc-placeholder.svg "")
冯诺依曼结构的计算机性能优化的秘密就是尽可能往金字塔的高层走。cpu只是一个执行指令的机器，我们要做的就是无限压榨，抢占cpu的时间片。

栈结构非常快，尤其是c/c++中的栈结构，各大cpu指令集也针对栈做了专门的优化（如x86的esp,ebp，pop,push指令）,这使得字节码的执行可以在cpu寄存器中执行，获得比在内存直接翻译成宿主代码几个数量级的速度提升。

## 结语
我们了解编译器 学习编译原理从实用主义的视角来看没有什么意义，因为现代编译器是非常复杂的，和我们写的玩具完全不是一个级别。

编译器的功夫都在编译器的后端优化，语言只是RFC，只是语法规定，具体的性能全都依赖于编译器的实现。

但是仍然在编程语言之外有很多用处，比如：

1. 定义我们需要的DSL，如jira创造了属于jira的查询语言。
2. 处理复杂的，非正则的文本。
3. 业务代码的更多可能性。
