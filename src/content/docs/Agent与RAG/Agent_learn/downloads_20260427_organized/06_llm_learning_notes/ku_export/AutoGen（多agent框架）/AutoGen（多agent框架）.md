# AutoGen（多agent框架）
一、什么是 AutoGen项目地址：https://github.com/microsoft/autogen

AutoGen 是一个框架，支持使用多个代理来开发 LLM 应用程序，这些代理可以相互对话来解决任务。 AutoGen 代理是可定制的、可对话的，并且无缝地允许人类参与。它们可以采用 LLMs、人工输入和工具组合的各种模式进行操作。

二、使用在 AutoGen 中，代理是一个实体，可以向其环境中的其他代理发送消息并从其他代理接收消息。代理可以由模型（例如 GPT-4 等大型语言模型）、代码执行器（例如 IPython 内核）、人类或这些以及其他可插入和可定制组件的组合来支持。

![](/personal-site-mvp/img/doc-placeholder.svg)

ConversableAgent此类代理的一个示例是内置ConversableAgent，它支持以下组件：LLMs 列表、代码执行器、函数和工具执行器、用于保持人在循环中的组件

创建一个基础代理ConversableAgent：

import osfrom autogen import ConversableAgentagent = ConversableAgent(    "chatbot",    llm_config={"config_list": [{"model": "gpt-4", "api_key": os.environ.get("OPENAI_API_KEY")}]},    code_execution_config=False,      function_map=None,     human_input_mode="NEVER",  )要求代理生成问题的响应使用generate_reply方法：

reply = agent.generate_reply(messages=[{"content": "Tell me a joke.", "role": "user"}])print(reply)多角色对话为代理分配角色并让他们参与对话或互相聊天。对话是代理之间交换的一系列消息。然后可以使用这些对话来推动任务取得进展。

通过设置两个代理的 system_message 为其分配不同的角色。

cathy = ConversableAgent(    "cathy",    system_message="Your name is Cathy and you are a part of a duo of comedians.",    llm_config={"config_list": [{"model": "gpt-4", "temperature": 0.9, "api_key": os.environ.get("OPENAI_API_KEY")}]},    human_input_mode="NEVER",  # 默认情况下，代理将在每次收到消息时提示人工输入。而在本例中我们将human_input_mode默认设置为“NEVER”即无需人工参与。)joe = ConversableAgent(    "joe",    system_message="Your name is Joe and you are a part of a duo of comedians.",    llm_config={"config_list": [{"model": "gpt-4", "temperature": 0.7, "api_key": os.environ.get("OPENAI_API_KEY")}]},    human_input_mode="NEVER",     max_consecutive_auto_reply=1,  # 中断方式1: 如果对同一发件人的自动响应数量超过阈值触发终止。    is_termination_msg=lambda msg: "good bye" in msg["content"].lower(),  # 中断方式2: 如果接收到的消息包含单词“TERMINATE”触发终止。)设置两名喜剧演员经纪人，请他们开始一场喜剧表演。使用 initiate_chat 方法来开始对话，将 max_turns 设置为 2 以保持对话简短。

result = joe.initiate_chat(cathy, message="Cathy, tell me a joke.", max_turns=2)触发终止通过配置ConversableAgent的参数实现。

max_consecutive_auto_reply 自动响应数量超过阈值触发终止is_termination_msg 接收到的消息满足条件触发终止人工反馈人工循环组件位于自动回复组件之前。它可以拦截传入的消息并决定是将其传递给自动回复组件还是提供人工反馈。通过配置ConversableAgent的human_input_mode参数实现。

![](/personal-site-mvp/img/doc-placeholder.svg)

NEVER ：从不请求人工输入。TERMINATE （默认）：仅当满足终止条件时才请求人工输入。请注意，在此模式下，如果人员选择拦截并回复，则对话将继续，并且 max_consectuive_auto_reply 使用的计数器将被重置。ALWAYS ：始终请求人工输入，并且人工可以选择跳过并触发自动回复、拦截并提供反馈或终止对话。请注意，在此模式下，基于 max_consecutive_auto_reply 的终止将被忽略。代码执行器代码执行器是一个组件，它接收输入消息（例如，包含代码块的消息）、执行执行并输出消息和结果。 AutoGen 提供了两种类型的内置代码执行器，一种是命令行代码执行器，它在 UNIX shell 等命令行环境中运行代码，另一种是 Jupyter 执行器，它在交互式 Jupyter 内核中运行代码。

对于每种类型的执行器，AutoGen 提供两种执行代码的方式：本地执行和在 Docker 容器中执行。一种方法是直接在运行 AutoGen 的同一主机平台（即本地操作系统）中执行代码。它用于开发和测试，但对于生产来说并不理想，因为 LLM 可以生成任意代码。另一种方法是在 Docker 容器中执行代码。下表显示了代码执行器和执行环境的组合。

| Code Executor  | Environment | Platform |
| --- | --- | --- |
| LocalCommandLineCodeExecutor | Shell | Local |
| DockerCommandLineCodeExecutor | Shell | Docker |
| jupyter.JupyterCodeExecutor | Jupyter Kernel (e.g., python3) | Local/Docker |

在本章中重点关注命令行代码执行器。

本地执行​![](/personal-site-mvp/img/doc-placeholder.svg)

本地命令行代码执行器收到带有代码块的消息后，首先将代码块写入代码文件，然后启动新的子进程来执行代码文件。执行器读取代码执行的控制台输出并将其作为回复消息发送回来。

运行打印随机数的 Python 代码块。创建一个带有代码执行器的代理，它使用临时目录来存储代码文件。

与本地命令行代码执行器类似，docker执行器从输入消息中提取代码块，并将其写入代码文件。对于每个代码文件，它都会启动一个docker容器来执行代码文件，并读取代码执行的控制台输出。

executor = DockerCommandLineCodeExecutor(    image="python:3.12-slim",     timeout=10,     work_dir=temp_dir.name, )构造函数中的work_dir指向本地文件系统目录，就像本地执行情况一样。 docker容器会挂载这个目录，执行器写入代码文件并输出到其中。
