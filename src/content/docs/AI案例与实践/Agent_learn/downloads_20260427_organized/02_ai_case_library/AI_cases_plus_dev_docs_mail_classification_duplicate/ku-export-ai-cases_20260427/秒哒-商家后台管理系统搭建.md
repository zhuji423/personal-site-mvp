## 2. 新手路线
#### 2.1 场景说明（以订单管理后台为例）
本示例展示一个典型的**交易与库存管理场景**，适用于电商、批发、餐饮等行业。系统包含以下核心页面与功能模块：

* **商品管理**：商品信息录入与更新，支持库存同步；
* **下单流程**：客户下单后自动扣减库存；
* **客户与发货管理**：查看订单状态并触发发货提醒；
* **库存与结算自动化**：实现库存预警与每日自动结算。

该示例场景的目标是：通过一套可读可改的数据库后台，配合自动化逻辑，完成从**下单 → 发货 → 结算**的完整业务闭环。后续案例将围绕这一场景展开，展示具体的页面结构与数据交互流程。

### 2.2 步骤一：搭建应用
1. 登录[秒哒平台](https://www.miaoda.cn/)。

![](/personal-site-mvp/img/doc-placeholder.svg "")
2. 在对话框，输入需求。

#### 需求撰写小贴士
为了让系统快速理解你的业务逻辑，建议在描述中尽量包含以下信息点：

1. **角色与场景**

    * 指出“谁”在使用系统，以及“在什么场景”中使用。
    * 示例：
        * “我是餐饮店老板，需要一个外卖订单管理后台。”
        * “我是健身房教练，需要一个课程预约系统。”


2. **核心目标 / 业务动作**

    * 说明系统要实现的主要目标或自动化逻辑。
    * 示例：
        * “下单后自动扣减库存、生成发货提醒。”
        * “学员报名后名额自动减少，并在开课前提醒。”


3. **涉及的关键页面或功能模块**

    * 简要列出你希望系统包含的主要页面或功能。
    * 示例：
        * “页面包括：商品管理、下单、今日订单、库存预警。”
        * “功能包括：会员积分、生日券、沉睡唤醒。”


4. **数据或流程关系（可选）**

    * 若有具体业务逻辑，可简单说明数据之间的关系。
    * 示例：
        * “每个订单对应多个商品；每日自动汇总销售额。”
        * “课程-场次-学员报名形成完整闭环。”

### 2.4 步骤三：确认数据库是否生成成功
打开「数据库」页后，你会看到表格区域：

* 如果页面里有类似**products / orders** 的表名，说明数据库已经生成；

> 这些表是由系统根据你在前一步输入的业务需求，由大模型自动推理并生成的。
> 模型会分析语义中涉及的业务实体（如「订单」「商品」「客户」「库存」等），并为它们建立对应的数据表，同时自动识别它们之间的关系（如订单关联商品、客户关联订单等）。
> 举例：当你输入需求 “我要做一个电商订单管理后台”，系统会自动识别出：
> * `products`（商品表）负责存放商品信息，如名称、库存、价格；
> * `orders`（订单表）用于记录订单编号、客户信息、下单时间等；
> * `order_items`（订单明细表）用于描述每个订单中具体包含哪些商品；
> * `customers`（客户表）保存客户姓名、电话、地址、标签等信息；
> * `stock_records`（库存表）追踪库存变化与预警。
> 
* 表中有列名（例如 `id`、`商品名称`、`库存`、`价格`），说明字段结构正常；

每个表中的列字段，都是根据语义中提到的数据要素自动提取的。系统会尽量生成与你业务逻辑相符的字段类型（如数字、文本、日期等）。

* 如果不符合你的业务逻辑（比如字段太少、命名不对），别慌——可以直接在对话中修改。

💬 **示例：**

> 「在订单表新增字段：客户手机号（文本）、订单来源（选项：淘宝/抖音/线下）」
> 「把商品表的库存字段设为默认值 100」
系统会自动调整数据库结构。

### 2.5 步骤四：数据库维护：可视化表格编辑
✅ 初始化数据库：上传你的第一批数据

**为什么要批量上传数据？**

在搭建好数据库结构后，系统虽然已经自动生成了数据表（如 `products`、`orders`、`customers` 等），但表中还没有真实数据。

要让页面中的“商品列表”、“订单记录”、“库存统计”等模块能正常显示与联动，就需要导入一批初始数据作为系统的“起点”。

1. 打开左侧菜单 → 点击「数据库」；

![](/personal-site-mvp/img/doc-placeholder.svg "")
2. 找到要导入的表（例如「商品表」或「orders」）；

![](/personal-site-mvp/img/doc-placeholder.svg "")


3. 点击顶部的【导入】，上传 CSV 文件；

![](/personal-site-mvp/img/doc-placeholder.svg "")
![](/personal-site-mvp/img/doc-placeholder.svg "")
4. 系统自动识别字段，支持字段名匹配与类型校验；导入完成后，可立即在界面查看或编辑。

![](/personal-site-mvp/img/doc-placeholder.svg "")


🔗 数据表与应用功能的对应关系

在秒哒中，每个页面展示的内容、每个功能模块的运行逻辑，**都直接依赖数据库中的数据表**。

你在后台维护的数据，并不会“孤立存在”——它们会实时映射到前端应用中，用于驱动页面展示与交互。举个具体例子（以电商/批发订单后台为例）：

|数据表|存储内容|应用端展示 / 功能体现|
|-|-|-|
|**products（商品表）**|商品名称、价格、库存、状态等|页面中的“商品列表”“商品详情”模块读取此表数据；下单时会扣减库存。|
|**orders（订单表）**|客户下单信息、订单编号、金额、状态|“今日订单”“订单详情”页面展示；用于每日结算。|
|**order_items（订单明细表）**|每个订单中包含的具体商品及数量|订单详情页面的商品明细部分。|
|**customers（客户表）**|客户姓名、联系方式、标签、备注|“客户管理”或“会员档案”页面的数据来源。|
|**stock_records（库存记录表）**|每次出入库变动记录（数量前后对比、来源说明）|在“库存日志”或“库存预警”页面展示；用于库存自动计算。|
