并发共享变量写入未加锁检测与修复

#### 🧑‍🏫 案例作者：[@刘鑫](https://ku.baidu-int.com?t=mention&mt=contact&id=a483af20-fce1-11f0-82db-53cf422ac20b)
#### 🎬 案例场景：开发
#### 🔧 使用工具：Comate
#### 📒 案例概要：本文介绍了并发共享变量写入未加锁检测与修复规则，旨在消除Golang并发代码中的数据竞争风险。规则通过模式匹配定位并发逻辑，闭包分析捕获共享变量，并检测锁保护机制。对于未加锁的共享变量写入，自动插入sync.Mutex保护，确保程序稳定性和可靠性。规则还提供了修复效果验证步骤，确保修改后的代码符合Go最佳实践。
# 规则概述
|**规则名称**|**并发共享变量写入未加锁检测与修复 (Data Race Protection)**|
|-|-|
|**治理目标**|消除 Golang 并发代码中因**共享变量未加锁写入**导致的 **Data Race** 风险。|
|**解决问题**|预防程序出现不可预测的 **Panic**、**结果不一致**或**内存损坏**等致命错误，提升系统的稳定性和可靠性。|
|**技术手段**|模式匹配 + **自动插入 **`sync.Mutex` 保护。|
|**风险等级**|数据竞争是 Go 语言中最危险的 Bug 之一|



# 核心技术原理与检测策略
## 检测步骤
|**阶段**|**核心动作**|**策略与技术依据**|
|-|-|-|
|**A1 定位并发逻辑**|**模式匹配**|准确识别所有启动并发执行的模式：`go func()`、`wg.Add/Wait`、`errgroup.Go()`，确保检测发生在多线程环境中。|
|**A2 捕获共享变量**|**闭包/作用域分析**|追踪并发块的闭包，识别**捕获自外部作用域**且在并发块内发生 `=`、`++`、`append`、`map[...] =` 等**写操作**的变量。|
|**A3 检测锁保护**|**模式校验**|验证共享变量的写操作是否被有效的**线程安全机制**保护：`sync.Mutex/RWMutex`、`atomic.*` 操作、`sync.Map` 或 **Channel 同步**。|
|**风险标记**|**交叉验证**|若 **(并发写入) AND (共享变量捕获) AND (无有效保护)**，则标记为 **并发风险点**。|



## 修复策略优先级
|**优先级**|**变量类型 / 场景**|**修复方案**|**介入等级**|
|-|-|-|-|
|**高优先级**|局部或函数级捕获的 **简单变量写入** (`count++`)|**自动修复：** 插入 `mu.Lock()` / `mu.Unlock()`，并在函数顶部自动声明 `var mu sync.Mutex`。|自动修复|
|**中优先级**|局部或函数级捕获的 **复杂结构写入** (`map[...] =`)|**自动修复/建议：** 在写操作前后插入锁保护。 （修复后必须通过 `go test -race` 验证）。|自动修复|
|**低优先级**|**全局变量/结构体字段**(`GlobalVar = 1`, `struct.Field = 1`)|**风险提示：** 输出高风险报告，建议由工程师手动将锁定义为结构体字段或全局变量，再进行保护。|人工介入|



# 修复效果与验证
## 预期效果
|**效果描述**|**实施细节**|
|-|-|
|**消除 Data Race**|通过自动插入 `sync.Mutex`，从根本上杜绝了共享变量的并发写入竞争，确保程序执行结果的确定性。|
|**符合 Go 最佳实践**|鼓励在适当的作用域（函数级或闭包级）定义和使用锁，避免滥用 `atomic` 操作或不必要的 Channel 机制。|
|**最小侵入性**|自动修复仅涉及锁的声明和加/解锁语句，不对原有的业务逻辑产生任何副作用。|
|**高风险可视化**|针对难以自动修复的全局变量和结构体字段，生成独立的《高风险未修复清单》，强制人工关注和结构体设计优化。|

## 规则内容：
```
---
description: >
  自动检测并修复 Golang 代码中多线程（goroutine / 并发函数）共享变量写入未加锁的风险。
  该问题极易导致数据竞争、panic 或结果不一致。
  规则将自动识别多线程中对同一变量的写操作，若未进行加锁保护，则建议或自动插入 sync.Mutex 保护。
globs:
  - "*.go"
alwaysApply: false
---

# 1. 稳定约束（必须遵守）
- 【线程安全保障】任何共享变量（包括局部引用、闭包外变量、全局变量、结构体字段等）在多线程环境中被写操作时，**必须使用锁或 channel 机制保护**。
- 【非破坏性修复】修复时仅插入加锁/解锁逻辑，不改写原业务逻辑与其他相关代码。
- 【上下文约束】仅在函数内存在显式 `go func()`、`sync.WaitGroup`、`errgroup.Group` 等并发执行逻辑时才触发检测。
- 【变量限定】仅分析闭包外捕获变量或共享引用，不处理 goroutine 内部局部变量。
- 【验证要求】修改后 gofmt/go vet/go test ./... 必须全部通过。

---

# 2. 必读文件（按需）
read_file:
  - "**/service/*.go"
  - "**/pkg/**/*.go"
  - "**/utils/**/*.go"
  - "**/internal/**/*.go"

---

# 3. 执行阶段（A→D必须按顺序执行）

## A. 定位（Detect）

### A1. 定位并发逻辑
扫描以下并发模式：
- `go func(` 或 `go someFunc(`
- `wg.Add(` / `wg.Done(` / `wg.Wait()`
- `errgroup.Group.Go(`
- 并发 map 操作（如 `sync.Map`、`map[...] = ...` 出现在 go func 内）

### A2. 捕获共享变量
对于每个并发块：
- 解析闭包上下文，提取外部捕获变量；
- 标记捕获变量是否为可写（出现 `=`, `+=`, `append`, `map[...] = ...` 等写操作）。

### A3. 检测锁保护
在该函数作用域或闭包中，检测是否存在以下保护模式：
- `mu.Lock()` / `defer mu.Unlock()`
- `sync.Mutex` / `sync.RWMutex` 定义；
- `atomic.*` 操作（视为安全）；
- channel 写入（作为同步信号）；
- 使用 sync.Map 的 `Store()` / `LoadOrStore()`（视为安全）。

若共享变量被多个并发块写入，且上述保护机制均未检测到，则标记为 **并发风险点**。

若满足以下任意条件，则标记为 “安全 goroutine”，不进入风险分析：
- goroutine 内未捕获外部变量（闭包变量列表为空）；
- goroutine 捕获的仅为函数参数或局部常量；
- goroutine 内所有外部变量仅发生只读访问（无写操作：=、++、append、map 赋值等）；
- goroutine 启动逻辑无循环或仅执行一次（常见模式：定时器、延时任务）；
- goroutine 仅包含 Sleep / Log / Print / Channel Send / DB Query 等 IO 操作；
- goroutine 体内无对共享结构（map/slice/struct/global）的修改。

输出：
文件 / 行号 / 函数名 / 变量名 / 是否检测到锁保护 / 风险等级。

---

## B. 设计（Design）

### B1. 优先方案：自动插入锁保护（适用于局部共享变量）
若风险点存在局部变量写入，如：
```go
var count int
go func() {
    count++
}()
``` 
则自动添加：
```go
var mu sync.Mutex

go func() {
    mu.Lock()
    count++
    mu.Unlock()
}()
```
若函数体内已有定义 var mu sync.Mutex或者类似的变量，则优先复用。

### B2. 辅助方案：检测复杂结构（如 map / slice）
对于复杂类型写入：
```go
go func() {
    m["key"] = "value"
}()
``` 
则建议插入：
```go
mu.Lock()
m["key"] = "value"
mu.Unlock()
```

### B3. 提示方案：全局变量 / struct 字段写入
若检测到：
- 全局变量被并发写；
- struct.field 被多个 goroutine 修改；
- 则输出高风险提示（不自动修复）：
⚠️ 检测到共享变量 userData.ActiveCount 在多线程中被修改，存在数据竞争风险，建议添加锁保护。

## C. 修复（Fix）
- C1 自动生成加锁/解锁代码，并插入写操作前后。
- C2 若无锁定义，自动在当前函数或闭包顶部插入：
var mu sync.Mutex
- C3 若已有锁定义，则使用现有锁变量。
- C4 修复示例：
修复前：
```go
var total int
go func() {
    total++
}()
```
修复后：
```go
var total int
var mu sync.Mutex

go func() {
    mu.Lock()
    total++
    mu.Unlock()
}()
```

## D. 验证（Verify）
- 静态验证：
  - 运行 gofmt、go vet、staticcheck；
  - 使用 go run -race 检查数据竞争应减少或消除；
  - 确认插入的锁逻辑无语法错误。
- 单测验证：
  - 执行 go test -race ./...；
  - 验证加锁后竞态检测（data race）告警消失；
  - 验证无性能回退或逻辑异常。

# 4. 产物（Deliverables）
- 《并发变量写入风险检测报告》
  - 文件 / 函数 / 变量 / 是否并发写入 / 是否加锁 / 风险等级
- 《自动修复清单与代码 diff》
  - 展示自动插入锁保护的具体位置
- 《高风险未修复清单》
  - 包含全局变量、复杂闭包变量等需人工介入的风险项
- 《修复验证报告》
  - gofmt/vet/test/race 检测结果与修复后统计数据
```
