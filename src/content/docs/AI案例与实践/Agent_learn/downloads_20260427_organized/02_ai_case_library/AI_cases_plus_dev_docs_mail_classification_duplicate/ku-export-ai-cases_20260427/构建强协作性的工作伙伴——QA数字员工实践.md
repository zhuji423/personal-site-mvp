# 背景
过去几年，人工智能的浪潮几经更迭，而今年，“Agent”无疑成为最热的技术关键词之一。它让我们重新思考一个问题——AI不再只是“回答问题”的工具，而是能像人一样**理解意图、执行任务、与人协作**的智能体。Agent 的演进速度令人惊叹，每一次模型的升级、每一个工具生态的突破，都让它离“类人智能”的目标更近一步。

在质量保障领域，我们深切感受到这种变化带来的机会。测试过程庞杂而细腻，自动化脚本覆盖了标准化的部分，却仍有大量需要人力投入的细碎环节：数据生产、日志分析、异常定位、用例回归……这些工作虽然重要，却往往重复、耗时，甚至被工程师戏称为“脏活累活”。我们意识到——**这正是数字员工能首先为人类工程师分担压力、释放创造力的地方。**我们对数字员工的定位十分清晰：它不是人类的替代者，而是**强协作的智能伙伴**。它能理解上下文、顺畅沟通，像一位可靠的助理，随时响应指令、主动推进任务。更重要的是，我们**不希望为了AI而重塑流程，而是让数字员工自然嵌入现有体系**，去增强团队的工作方式、提升协作效率。

本文将分享我们在这条探索道路上的一些思考与技术实践：如何让数字员工真正融入业务流程，如何让它们具备类人的交互体验与任务执行能力，以及我们如何衡量这些智能体在真实业务中的价值与影响力。希望这篇文章能为大家在 Agent 技术落地的道路上，带来一些启发与灵感。

# 数字员工能力演进路径
为了构建真正具备强协作性的智能工作伙伴，我们在推进数字员工建设的过程中，经历了一个循序渐进、层层进化的技术演进历程。

![](/personal-site-mvp/img/doc-placeholder.svg "")
最初（**L0 聊天机器人阶段**），数字员工主要依托大语言模型完成业务问答与知识检索。它能够理解自然语言、提供辅助信息，但尚不具备与外部系统交互的能力，更多扮演“信息助手”的角色。

随着业务复杂度的提升，我们进入了**L1 同步工具调用者**阶段。此时数字员工已经能够在指令驱动下，调用预定义的工具或接口完成简单操作，实现“能说也能做”。然而，工具调用仍是同步执行的，工程师需要等待结果返回后才能继续任务。

为了进一步提升协作效率，我们在**L2 异步任务执行者**阶段引入了异步执行与上下文增强机制。数字员工可以在后台持续执行任务、监控状态，并在任务完成后自动汇报或触发后续动作。这意味着它开始具备“自主执行”与“任务编排”的能力，大幅减少人类的等待与干预成本。

进入**L3 业务流程驱动者**阶段后，数字员工不再局限于单个任务，而能理解业务内容并驱动完整的业务流程。它可以根据场景触发多工具协作，实现跨系统的自动闭环执行，真正成为“懂流程、会协作”的业务伙伴。

我们的最终目标是迈向**L4 AI 团队**阶段。在这一阶段，数字员工不再是单个智能体，而是由多个具备协作能力的 Agent 组成的智能团队。它们能够基于预设的协作关系与策略，共同解决更复杂的跨域问题，实现真正的“AI 团队自治与协同”。

# 构建强协作性数字员工的七大核心能力
要让数字员工真正具备“强协作性”，不仅需要智能算法的支撑，更需要在架构设计上全面对齐人类的工作方式与组织协作逻辑。我们将这一能力体系归纳为核心七要素：

![构建强协作性数字员工的七大核心能力](/personal-site-mvp/img/doc-placeholder.svg "构建强协作性数字员工的七大核心能力")
* 首先，**人类工作环境融入**。数字员工应当能够无缝嵌入企业现有的沟通与协作平台中，例如在百度的如流体系中，以“独立个体”的身份与人类同事进行自然交互。这种方式比让人类主动前往一个独立平台更高效、更自然。同时，数字员工需要具备多模态信息获取与理解能力，能处理人类给他的文本、图片、文件等多种信息形态。
* 其次，**异步交互**。通过异步任务引擎，数字员工可以在后台持续执行任务、管理状态，与人类工程师并行工作，实现“人不等机、机不等人”的高效协作模式。
* 第三，**上下文理解**。通过增强记忆模块，数字员工能够理解任务的历史背景、状态与意图，从而在多轮任务中保持连贯性和目标一致性。能对上文提及的人物进行灵活的查询、修改或终止。
* 第四，**业务能力进化**。数字员工应当能够通过人类的描述理解业务知识与操作流程——包括要做什么、步骤如何、可使用哪些工具——从而逐步掌握企业的专业技能体系并且能接受人类的输入，不断进化业务能力。
* 第五，**主动行动**。在某些场景中，数字员工应当能够主动推动任务进展、提醒风险、发起请求，而不仅仅是被动响应指令。
* 第六，**权限管控**。如同人类员工一样，数字员工应当受到完善的安全与权限体系管理，明确哪些数据可访问、哪些系统可操作，确保其行为在安全边界内受控。
* 最后，**工作过程可追溯**。每一次任务执行、工具调用与人机交互都应被记录，以便在出现异常时能够复盘、审计和持续优化，保障可解释性与合规性。

这七个要素共同构成了强协作性数字员工的技术基石——它不仅让数字员工能『像人一样工作』，更能在组织中『与人并肩工作』，成为人类工程师可信赖、可控且可成长的智能伙伴。下面我们将对这些能力进行详细拆解，介绍我们的一些具体实践。

## 人类环境融入
感知与交互，是让数字员工拥有『五官』和『行动力』的关键。我们认为，真正的数字员工，必须『像人一样』工作。过去的 AI 工具往往只能接受单一输入（如文字），一问一答、线性执行——做完一件事，才能开始下一件。但人类的工作方式从不是这样的。一个能真正替你分担工作的数字员工，应该能听懂语言、看懂文件、理解场景、同时处理多项任务，并在不同模态的信息中保持连贯的上下文理解。

基于这个认知，我们选择如流作为交互入口，而非独立网页或外部平台——因为这里才是真实的工作场景：任务讨论、文件传递、截图分享、会议纪要都发生在这里。让数字员工嵌入如流中，意味着它可以天然融入团队协作流，能在最自然的沟通环境下理解上下文、接受多模态输入（文本、图像、文件），并以异步方式处理任务、主动汇报进展。数字员工可以做到：

* **看懂文件**：从日报、测试报告或设计文档中抓取关键信息
* **听懂语义**：理解任务意图，而非仅仅匹配关键词
* **识别图片**：从截图或报表中提取指标、发现异常
* **多任务并行**：像同事一样同时跟进多项工作，不阻塞流程
* **理解上下文**：记得你上一次的指令，自动衔接任务，而非从零开始

换句话说，它不能只是『回答问题』，而是能像同事一样『理解场景，完成任务』。人类的工作方式是感知驱动的：你收到信息（文本/图片/文件/语音）→理解→执行→反馈。信息永远是多模态的、异步的、上下文相关的。如果数字员工还只能靠单一文本输入、即时对答、线性串行，那它永远只是『工具』，而不是『同事』。我们希望数字员工成为一个真正意义上的『同事型智能体』——它能在如流群聊中看到项目截图、读取任务文档、理解上下文，无需你重复指令，就能主动判断下一步行动。这样的交互方式，才是真正意义上**像人类一样的工作体验，彻底融入人类的工作环境。**

**数字员工要像人一样『有感官』，能看、能听、能理解多种信息形态**

## 异步交互
在人类世界的真实协作中，工作不是“一问一答”的顺序执行。我们收到信息、处理、等待反馈、再继续下一步——这是一个充满并行、异步、动态反馈的过程。一个真正能与人协作的智能体，不应该只在工具调用完成后才“说话”，而是像人一样，能同时处理多条任务、随时响应新事件、理解任务上下文，并主动汇报进展。基于这种认知，我们选择了事件驱动的架构，让对话系统自然嵌入工作流。

用户的每次请求都成为一个事件：实时任务即时响应，长耗时任务则以任务 handler 的形式持续追踪。当任务完成时，系统自动向 LLM 推送“任务完成事件”，由 LLM 生成最终回复。这意味着数字助理可以真正**持续在线地参与**工作，而不是被动等待。在这样的机制下，数字员工能够做到：

* **即时反馈**：长耗时任务不会阻塞交互，用户始终获得实时回应
* **多任务协同**：同时跟进多个任务的状态与进度，不遗漏任何结果
* **上下文理解**：跨事件保持任务语义连续，理解“谁”、“在做什么”
* **主动更新**：任务完成后自动汇报结果，无需人工催问
* **自然对话流转**：像同事一样在事件流中参与工作，不再是“命令式调用”

换句话说，这样的架构让对话系统从“应答机器”转变为真正的“协作伙伴”。它不仅能执行命令，更能**理解场景、感知进度、主动互动**。当系统能在事件流中理解上下文、异步响应任务、并持续对话时，它就不再是冷冰冰的工具，而是能与人共同工作的智能体。这，才是像人一样工作的强协作性工作伙伴。

![异步调度的处理逻辑](/personal-site-mvp/img/doc-placeholder.svg "异步调度的处理逻辑")
举例：你让数字员工对一批数据做质检，它会立刻接受任务，后台处理，完成后异步推送结果，期间你还可以让它做查询需求卡片等其他工作。

## 上下文理解
数字员工不仅能执行任务，更能**理解前因后果，在上下文中持续推进**。传统 AI 是『无记忆』的：一次指令、一轮任务，完成即止。而我们在实践中，通过上下文理解机制，让任务具备**记忆、关联与延续性**：

* **任务继承**：新指令自动关联前序任务或结果。例如先让它『数据质检』，再说『根据前面的数据，做个数据标注』，它能理解对象是谁。
* **状态追踪**：每个任务都有上下文状态（任务ID、进度、输入输出），可随时引用或恢复。
* **语义续作**：记得你的目标和未完成项，隔一段时间也能无缝继续。

![让数字员工对一批数据做质检，它会立刻接任务，后台处理。期间你还可以让对该任务的数据做数据标注工作](/personal-site-mvp/img/doc-placeholder.svg "让数字员工对一批数据做质检，它会立刻接任务，后台处理。期间你还可以让对该任务的数据做数据标注工作")
我们通过增加记忆能力和给数字员工更多上下文来提升其对上下文任务的理解能力。我们认为，**真正的智能，不在于模型回答得多准，而在于它能否『理解延续的世界』，能否形成『行为连续性』**。 记忆能力与上下文工程的本质，不是堆上下文、加数据库，而是让 AI 拥有时间维度的思考。具体说来，我们在实践中有如下思考：

* **记忆不是存储，是选择与提炼：**过去我们以为『让模型记住一切』就能变聪明，但实际上那会让它『被记忆淹没』。真正的智能记忆，必须像人脑一样具备『选择性注意』。知道什么该留下、什么该遗忘。这就是我们提出『记忆分层』的原因——短期关注上下文，摘要形成知识，长期沉淀经验。**遗忘机制的设计，与记忆机制同等重要，只有进没有出的记忆可能是个灾难。**

![短期记忆：上下文窗口管理 + 语义裁剪；中期记忆：自动摘要 + 任务状态追踪，越新的记得更牢、常用的更稳、久远的自然淡忘；长期记忆：主动式更新，事实卡片化存储 + 检索增强](/personal-site-mvp/img/doc-placeholder.svg "短期记忆：上下文窗口管理 + 语义裁剪；中期记忆：自动摘要 + 任务状态追踪，越新的记得更牢、常用的更稳、久远的自然淡忘；长期记忆：主动式更新，事实卡片化存储 + 检索增强")
* **上下文不是静态文本，而是动态状态：**很多工程误区是把上下文当成『prompt 拼接』。但真实世界的任务是连续的、有状态的。比如，一个项目讨论、一次测试分析、一次多轮决策，都不是独立对话，而是上下文驱动的状态演化。因此我们认为：上下文工程的核心，不是把『历史复制进来』，而是**让智能体理解任务处于哪个阶段、延续哪条逻辑链条。**就拿工具选择这个场景举例，在真实的业务场景中，数字员工往往面临一个问题——工具太多、调用成本太高。如果简单地将所有可用工具一次性暴露给大模型（LLM），不仅会造成推理负担过重，还可能导致工具调用错误或效率低下。因此，我们为数字员工设计了一套高效的工具槽位机制，让它能够像人类一样，在恰当的时机选择合适的工具。整个机制的核心思想是：“有限槽位 + 智能筛选 + 动态融合输出”。我们将工具按策略划分为三类，分别由 LRU（最近使用）、TOP（高频使用） 和 AI（智能分析） 三个模块负责管理和筛选。经过三层策略筛选后，系统会进行一次融合输出，将**最合适的一组工具**提供给 LLM 调用。这使得数字员工既能**保持轻量级推理**，又能**灵活应对复杂多变的任务场景**。
    * **LRU**（最近使用）策略模拟人类的“短期记忆”。系统假设用户更倾向于重复使用最近调用过的工具，通过记录近期工具调用历史，优先保留这些工具，避免知识切换和认知中断。
    * **TOP**（高频使用）策略利用长周期的调用统计数据，识别并锁定常用、高频的核心工具，确保这些工具不会因为缓存刷新而被替换掉。这相当于数字员工的“工作肌肉记忆”，提升常规任务的执行效率。
    * **AI**（智能分析）策略结合上下文语义、任务目标和对话内容，动态分析当前情境下可能需要的新工具。当数字员工面临新的业务需求时，AI 模块会智能发现潜在可用的工具，并动态填充到可用槽位中。




![LRU策略模拟人类的“短期记忆”；TOP策略识别并锁定常用、高频的核心工具，确保这些工具不会因为缓存刷新而被替换掉；智能策略结合上下文语义动态分析当前情境下可能需要的新工具](/personal-site-mvp/img/doc-placeholder.svg "LRU策略模拟人类的“短期记忆”；TOP策略识别并锁定常用、高频的核心工具，确保这些工具不会因为缓存刷新而被替换掉；智能策略结合上下文语义动态分析当前情境下可能需要的新工具")
* **记忆与上下文结合后，AI 才能形成『行为连续性』：**记忆的 AI，每轮都像刚入职的新员工。有记忆但没上下文结构的 AI，就像『碎片化笔记本』，记得一堆事，却不知道怎么串起来。只有两者结合，AI 才能建立起『自我一致性』——它知道自己在做什么、为什么做、下一步要做什么。**上下文是认知连续性的载体，记忆是认知演化的燃料。**
* **上下文工程让『Prompt』从静态模板变成动态系统：**过去我们写 prompt，就像写剧本。而上下文工程，是在实时生成『下一场戏』。它涉及信息筛选、优先级、检索、压缩、剪枝等工程逻辑。这让 AI 从『读剧本演员』变成『即兴演员』——能根据场景自我调度资源、调整语境。**Prompt 工程解决单轮问题，上下文工程解决时间跨度问题。**在数字员工memory体系的建设中，我们把“记忆+上下文工程”落地为一套工程体系，在这套架构的支撑下，数字员工拥有了真正“像人一样”的记忆力与理解力。

## 业务能力进化
要构建强协作性的数字员工，让其真正融入业务场景，就必须让它具备**持续理解业务知识、并随业务进化而自我成长**的能力。我们为此构建了一套以知识沉淀和动态学习为核心的机制，让数字员工能像人类工程师一样，在工作中积累经验、更新认知、优化行为。

* 首先，通过**知识沉淀**，业务专家的经验和判断被结构化地存储为配置与知识库内容，形成可复用的知识资产。这让经验不再依赖个体记忆，而能被数字员工直接调用。得益于**知识复用机制**，同一份知识库内容可以支撑多个业务场景的任务执行，既减少重复维护，又推动组织知识的共享与积累。
* 其次，得益于这种结构化设计，数字员工具备了**快速扩展**的能力——新业务的接入成本从“重新开发一套系统”，变为“编写配置 + 准备知识库文档”，大幅降低了建设和迭代门槛。在运行过程中，操作指南与知识库可以**持续优化**。当业务流程或策略调整后，只需更新知识内容，数字员工便能立即采用最新的规范与方法，无需重新训练模型，实现了轻量、灵活、实时的进化能力。

通过这一整套机制，数字员工从静态模型走向动态智能，能够在与人类共事的过程中不断学习、成长，并持续提升业务洞察与执行能力。

### 业务知识体系架构
* 存储在配置文件中
* 定义“做什么”、“怎么做”、“按什么顺序”
* 告诉数字员工执行步骤、调用哪些工具、如何处理分支逻辑
* 由业务专家编写，形成可复用的流程模板
* 存储在知识库（KU）系统中
* 包含具体的业务知识、规则文档、教程手册、最佳实践等
* 通过 `knowledge_agent` 的工具（如 `get_ku_content`、`get_tutorial`）动态获取
* 由业务团队维护，确保知识始终是最新的

### 业务流程、知识、工具持续注入，让数字员工的业务能力不断进化
### 操作流程配置：定义执行骨架
以“上线检查”场景为例，业务专家在配置文件中描述操作流程：

```
online_guard:  # 业务场景名称
  coordinator: |
    【上线检查场景操作指南】
    你的任务是根据上线审批教程手册的指引，完成上线检查。执行步骤如下：
    1. 获取教程手册
       - 调用 knowledge_agent.get_tutorial 获取上线审批的教程手册
       - 按照手册中的规则执行检查，不要自行推断
    2. 处理用户输入的链接
       - 如果输入是 iCafe 链接：调 analyzer_agent.get_icafe_info 获取需求卡片信息
       - 如果输入是知识库（KU）链接：调 knowledge_agent.get_ku_content 获取文档内容
    3. 检查与输出
       - 按教程手册中的检查规则，对卡片状态、Bug状态、报告绑定、报告结论等逐项判断
       - 输出需符合教程手册规定的表格格式
```
这个配置告诉数字员工：

* **执行顺序**：先获取教程手册，再处理链接，最后执行检查
* **工具调用**：需要调用 `knowledge_agent.get_tutorial`、`analyzer_agent.get_icafe_info` 等工具
* **判断逻辑**：根据输入类型（iCafe链接 vs 知识库链接）选择不同的处理方式
* **输出规范**：结果需要符合特定的表格格式

### 业务知识库：提供动态内容
当数字员工执行到“获取教程手册”这一步时，它会调用工具：

1. 连接到知识库系统（KU）
2. 根据配置的文档ID，获取最新的上线审批教程手册
3. 将手册内容返回给数字员工

这样，即使业务规则发生变化，业务团队只需更新知识库中的文档，数字员工就能自动获取最新规则，无需修改配置文件。

### 静默唤醒方案
我们认为，未来数字员工的一个发展方向，是实现从被动对话到主动智能的关键跃迁。这一跃迁的核心价值在于，数字员工能在复杂交互场景中，从多用户产生的海量信息中精准提取关键内容，主动发挥规划与执行能力，以更低的人机交互成本、更高效的响应速度满足用户需求。例如，当前群聊场景下的数字员工应用仍存在『需要先@数字员工，他才能工作』的问题，由于无法像真人一样感知群聊历史对话内容并主动识别潜在需求，用户每次与数字员工交互时，都必须通过@唤醒，并重复复述群聊中已形成的结论或需求，这不仅增加了操作成本，也无形中降低了服务效率。

针对这一问题，我们打造了静默唤醒的方案，采用滑动窗口技术对群聊上下文进行实时摘要总结，同步结合小参数模型与延迟响应机制，对群聊内容进行持续的唤醒意图分析。此举能让数字员工保持“待命状态”，在识别到用户需求时主动发起回复，同步完成任务规划与执行，无需用户重复触发或复述需求，真正实现主动智能服务。在静默唤醒的方案设计中，我们解决了这几个问题，对唤醒的效率、成本、效果进行平衡：

* **原始对话窗口**：保留足量原始对话直接输入至大模型，降低因群聊总结带来的幻觉，队里溢出则加入至缓存队列
* **缓存队列**：缓存队列打满后再触发群聊总结，降低群聊总结频率
* **延迟触发控制**：通过设定延迟触发时间，延迟触发时间内有新群聊，则刷新延迟触发时间，降低静默唤醒频率
* **多模型策略**：使用小参数模型仅对唤醒意图识别和历史群聊总结，唤醒后使用大参数模型进行任务规划，降低静默唤醒成本、提高效率

## 权限管控
数字员工权限管控应该以**最小权限原则**为核心，通过动态授权、职责分离和细粒度控制，实现安全与效率的平衡。其本质是构建“权责对等”的访问体系，确保数字员工仅能访问职责范围内的数据与系统，同时通过审计追溯保障合规性。原则上我们进行数字员工权限控制设计的时候，需要从以下三个方面思考：

* **风险驱动逻辑**：数字员工若权限过宽，可能引发数据泄露、操作越权等风险；若权限过窄，则影响业务效率。需基于业务场景（如财务对账、客户管理）明确权限边界。
* **动态适配需求**：企业业务流（如项目制、跨部门协作）常变，需通过动态授权机制（如审批通过后自动提权）适应角色变动、流程调整。
* **合规与效率平衡**：需满足GDPR、网络安全法等合规要求，同时避免过度管控导致协作效率下降。

目前我们通过3个层面进行了权限控制

## 工作过程可追溯
数字员工的工作过程追溯是以**全流程透明化、全流程操作留痕、可审计性**为核心，通过任务分解记录、输入输出日志、可解释性分析、版本控制手段，构建“任务-输入-模型推理-输出-决策依据”的完整证据链，实现从任务接收到执行完成的全链路可追溯，支撑信任建立、合规验证与持续优化。其本质是破解大模型“黑箱”难题，将生成式AI的“不可知”转化为“可验证”，确保每一步决策均有据可查、有因可溯。过程可追溯的设计方式需要从下面几个方面考虑：

* **大模型特性驱动需求**：大模型具有强生成能力但存在“黑箱”特性，决策过程不透明，需通过过程追溯解释“为什么生成这个结果”，增强用户信任。
* **业务优化需求**：通过分析历史操作数据，可发现模型性能瓶颈（如特定场景下响应错误率上升），指导模型迭代与参数优化，提升生成质量与效率。
* **风险防控逻辑**：若操作无记录，一旦发生生成内容偏差、数据泄露或业务异常，难以定位问题根源，需通过追溯实现“操作可回溯、责任可界定”。
* **数据的可观测: ** 我们通过数据的可观测，可以明显的分析用户的使用情况和行为，对于我们的数字员工的迭代优化，提供可视化数据支撑。

为了数字员工的**工作过程可追溯**实现，我们在使用过程中引入了专门的工作台进行日志以及执行过程的记录，在数字员工工作台上，用户可以查看数字员工为『我』执行的任务，**展示详细的工作过程**。开发者可以通过API接入，**无需开发前端页面**即可灵活的展示复杂的工作过程及结果预览。如下图所示，通过工作台可以完整的记录某个任务所有的中间的工作过程。这样对数字员工的执行逻辑一目了然，出现报错也可以快速进行问题定位和修复。

![数字员工的任务执行过程可以在工作台看到](/personal-site-mvp/img/doc-placeholder.svg "数字员工的任务执行过程可以在工作台看到")
在整体用户使用数据观测方面，工作台也给出了答案，数字员工接入工作台之后。工作台会对数字员工的数据进行自动化统计分析。帮助用户分析及数据漏斗模型。开发者可以分析数字员工的任务触发率、成功率、采纳率，用户在如流、DevOps平台上的转换率以及一些任务的使用情况分析等。

![使用漏斗图来分析数字员工的任务转化](/personal-site-mvp/img/doc-placeholder.svg "使用漏斗图来分析数字员工的任务转化")
数字员工工作过程追溯通过技术赋能与管理闭环，在保障安全合规的同时，提升故障排查效率、优化业务流程，成为企业数字化转型中“可信赖、可追溯、可优化”的关键支撑。



# 评估数字员工的业务影响力
为了全面衡量数字员工在业务中的实际影响力，我们持续优化和迭代数字员工的牵引能力，设计了一套系统化的指标体系，用于量化数字员工在各类业务场景中的贡献和价值。这套指标体系主要涵盖业务场景渗透、人员渗透与体验，以及成本效益三个维度，从多角度反映数字员工在组织中的实际作用。

|**维度**|**指标**|**含义**|
|-|-|-|
|**业务场景渗透**|**场景参与度**|这个指标反应数字员工在各个业务场景的渗透**广度**，目的是牵引我们让数字员工参与更多的场景。各业务根据自己的情况设定场景，例如终端测试、服务端测试、数据生产、效果评测、资源运维等，每个场景都对应QA日常一项相对**完整**的测试任务（类比『工单』的概念）|
|****|**场景介入深度**|这个指标牵引数字员工在每个场景能深入的完成整个工作的全部工序，人类只做必要的最小介入。上述每个场景均有一个介入深度，其估算方法为：数字员工可以独立完成的工序数/该场景的全部工序数。随着技术的不断进步，每个场景越来越多的工序都能由数字员工执行，即场景介入深度不断提升。|
|****|**场景提效比例**|这个指标反映数字员工的接入理论上能让每个场景的执行时长缩短多少。可以牵引未来不断优化技术，让各个场景执行时长进一步缩短。|
|****|**实际工作承载率**|该指标衡量实际工作中有多少测试任务（即上面的『场景』的实例）是由数字员工『承载』的。例如一次提测，如果50%的工序都是由数字员工完成的，则可以计入分子。分母为QA所有的测试任务量。|
|**人员渗透和体验**|**全角色渗透率**|数字员工除了被QA使用外，还可以给其他角色使用。使用全角色渗透率来度量这个指标：分母是各个数字员工在自身业务上最多能影响的人数分，分子是当前已经影响到的人数（被使用）。|
|****|**PV**|在QA的场景映射为一次任务执行|
|****|**UV**|QA、RD、PM等使用过数字员工的人数。|
|****|**NPS打分**|面向数字员工用户们发出调研问卷，对数字员工的体验进行NPS打分|
|**成本**|**投入产出比**|从投入和产出的角度进行调研，折算成人时，看数字员工项目的投入产出比。投入人时为各数字员工统计投入了多少成本；产出人时为由于数字员工的加入给项目带来的效率提升时长|

各个指标的关系如下图所示：

![数字员工业务影响力指标关系示例](/personal-site-mvp/img/doc-placeholder.svg "数字员工业务影响力指标关系示例")
经过一段时间的建设，我们的各个数字员工已经在业务中形成了一定的影响力。当前有71%的场景有数字员工参与，这些场景涵盖数据生产、回归测试、效果评估、运维监控等工程师的日常工作。其中数字员工的介入深度平均为52%，即有一半工序有数字员工的参与，这带来了37%的效能提升。同时，我们也看到，当前只有28%的工作是由数字员工『承载』的（参与了大于50%以上的工序才算成『承载』）。这为我们后面的发展指明了方向。未来，我们**要不断提升数字员工的介入深度，让他们能承载越来越多的工作**。同时要进一步提升全角色渗透率，除了QA，让RD和PM同学都用起来。

# 未来展望
未来，我们会在业务渗透、协作模式与协同能力三大维度实现跨越式发展，成为驱动组织效率升级的核心力量。

* 在业务影响力提升上，技术迭代将成为核心驱动力。通过持续优化算法模型、深化场景适配能力，数字员工的业务介入深度将实现从50%到80%的关键突破，从辅助性参与转向核心环节渗透。这一提升将直接推动工作承载率从28%跃升至40%，让数字员工承接更多重复性高、规则性强的业务场景，甚至涉足部分决策支持类工作，大幅释放人力资源投入高价值创新领域，强化其在业务链条中的不可替代性。
* 协作模式将完成从“伙伴”到“流程驱动者”的角色蜕变。当前数字员工仅能在零散场景实现主动自驱（如上文提到的提测准出流程驱动、静默唤醒等场景），未来将打破场景壁垒，深度嵌入业务全流程。通过对流程节点的精准把控、任务流转的智能调度，数字员工将成为流程推进的核心枢纽，主动触发任务分配、进度追踪与问题预警，驱动相关人员高效协同，彻底改变“人推动流程”的传统模式，构建“数字员工驱动流程、流程赋能人”的全新协作生态。
* 多数字员工协同将突破单一角色局限，迈向复杂场景攻坚。未来数字员工将告别仅聚焦“脏活累活”的定位，通过构建协同机制形成“数字员工矩阵”。不同专业领域的数字员工可依据场景需求快速组队，分工完成数据采集、分析建模、方案生成、执行落地等全链条工作，攻克跨领域、高复杂度的业务难题，为组织应对复杂挑战提供全新解决方案。
