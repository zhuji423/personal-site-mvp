电商-基于规则体系的前端视频化提效

#### 🧑‍🏫 案例作者：[@黄泽滨](https://ku.baidu-int.com?t=mention&mt=contact&id=f68f4030-fcec-11f0-bd9d-69eb8dc313a3)
#### 🎬 案例场景：开发
#### 🔧 使用工具：Codex
#### 📒 案例概要：本文介绍了电商搜索部通过制定可执行的规则体系，解决视频生成/封面/合成链路长、依赖多的问题，降低沟通成本，提升开发、联调、交付效率。设计原则包括分层、统一入口配置和领域特化，规则亮点涵盖目录职责、流水线标准化、质量硬门槛等，结合技术文档和自动化工具，实现视频流水线的全链路提效。
## 背景与目标
* 视频生成/封面/合成链路长、依赖多（模板、字体、Chromium、ffmpeg、BOS），新人和 AI 都容易踩坑；评审缺统一检查项。
* 目标：用可执行的规则压缩沟通成本，让人/AI 按同一套路开发、联调、交付。

## 设计原则
* 分层：`AGENTS` 速览 + 章节细则，区分“信息类”（结构/依赖/命令）与“指令类”（必须执行的 lint/截图/样例）。
* 统一入口配置：`.codex/codex.config.json` 把所有规则/技术文档的路径列清楚，AI 或工具可以直接按 00–90 编号和 extras 定位所需内容，不用手动翻找。
* 领域特化：针对视频流水线单独建章和 API 速览，覆盖 `/api/vid_vid`、透明背景、字体预热、Chromium 并发/缓存策略。

## 规则与文档地图
* 入口：`AGENTS.md`（命令、提交流程、核心约束、导航）。
* 细则：`docs/ai-rules/00-90`（基础、结构、编码、组件/状态、数据/副作用、视频流水线、日志、质量/测试、Git/PR、API 速览）。
* 技术补充：`docs/tech/index.md`（索引，按需查阅），`docs/tech/html-to-video-api.md`（HTML→视频能力拆分与接口）、`docs/tech/puppeteer-timecut-upgrade.md`（Puppeteer/Timecut/Chromium 升级与性能）、`docs/tech/docker-build-gotchas.md`（容器构建注意事项）。
* 引用：`.codex/codex.config.json` 列出常驻规则与按需技术文档供 Agent 读取。

## 规则亮点
* 目录职责：`pages` 轻装配、逻辑下沉 `lib`/`hooks`/`utils`，常量/类型集中；临时产物统一在 `.next/server/video`、`.next/server/temp/html`。
* 流水线标准化：`/api/vid_vid` 分步说明、透明背景输出、字体/Chromium/ffmpeg 前置、并发与缓存处理；覆盖 HTML→视频通用能力与 Puppeteer/Timecut 升级方案。
* 质量硬门槛：任何改动（人或 AI）必须跑 `npm run lint`；逻辑改动补同目录测试；媒体改动需样例 URL/GIF+命令输出。
* UI 交付：明显版式/交互改动需前后对比或 GIF，微调可文字说明，附可访问路由。
* 日志/可观测：Winston JSON 规范（event/status/endpoint/template/duration_ms/error/extra），无独立埋点时用日志兜底。
* 提交流程：`DS-xxxx [Story] 描述`，PR 必含背景/方案/测试证据/受影响路由与回滚策略。

## 使用指南
* 新人/Agent：先读 `AGENTS.md`，按导航跳转；改动前确认目录归属和流水线依赖。
* 技术问题：先看 `docs/tech/index.md`，按需加载对应技术文档，避免一次性拉全量上下文。
* 评审：以章节为 checklist（结构/类型/副作用/UI 交付/日志/测试），缺截图或 lint 结果直接打回。
* 自动化：CI 至少跑 `npm run lint`，可在 PR 模板增加 UI 交付/媒体样例/测试清单勾选。

### 故障排查沉淀
* 归档位置：技术类排障优先放在 `docs/tech/` 下（可建 `troubleshooting/` 目录或单页），按主题拆分，如 Chromium/Timecut、BOS 上传、ffmpeg 合成、API 常见错误等。
* 索引：在 `docs/tech/index.md` 补充入口，便于按需检索；若成为“必遵守”的规则，再考虑在 `docs/ai-rules` 增补章节并更新 `AGENTS.md` 导航。
* 引用：新增排障文档后更新 `.codex/codex.config.json` 的 `extras`，让 AI/工具按需读取，不必一次性加载全部。

### AI Coding 引用策略
* 背景：团队使用的 AI 工具多样，统一通过“引用配置”提供上下文，避免在规则里塞满特定助手的指令。
* 做法：在 `.codex/codex.config.json` 的 `docs`（常驻规则）和 `extras`（按需技术文档）维护路径，AI 工具读取配置获取上下文。
* 新文档示例：新增 `docs/tech/foo-bar.md`，在 `extras` 追加：

```
{
  "extras": [
    "../docs/tech/index.md",
    "../docs/tech/html-to-video-api.md",
    "../docs/tech/puppeteer-timecut-upgrade.md",
    "../docs/tech/docker-build-gotchas.md",
    "../docs/tech/foo-bar.md"
  ]
}
```
* 不同 AI 工具按各自方式引用 `.codex/codex.config.json` 即可，无需在规则正文重复配置。
* MCP 使用场景（当前接入）：
    * `fetch`：实时获取外部 HTTP 内容或最新信息，避免手写爬虫。
    * `context7`：检索公共库/框架文档（resolve-library-id/get-library-docs）以查 API/用法，优先于搜索引擎。
    * `chrome-devtools`：本地/远程页面调试场景，需排查浏览器端行为时使用。
    * `playwright`：需要浏览器自动化/交互验证时调用。
    * `github`：访问 GitHub 资源时使用（需 Bearer token）。

* 使用原则：先用 `.codex/codex.config.json` 提供的文档上下文；只有当本地文档不足或需实时信息/调试时，按需调用上述 MCP，避免无关调用占用上下文。
