# 创意构思：构建输入query
**🌺【应用创意】**：**首先我们需要从应用名称、工作流程、应用需要的功能/插件能力3个层面进行构思**

对于本教程，我们想要制作一个插画故事板生成器。

具体的工作流程：

1. 用户可以输入大致的故事概览 

2. 大模型生成完整故事

3. 大模型根据故事情节拆解分镜头

4. 大模型输出对应的分镜插画

需要调用的能力：大模型文本生成、大模型文生图



**🧑‍🎨【query设计思路】：有了大致的应用创意梳理，我们就可以开始构建提示词了，要保证提示词包括以下关键信息**

1. 澄清应用名称
2. 向大模型描述应用的工作流程
3. 明确的@需要调用的插件

```
#Query示例：
生成一个插画故事版生成器。
用户先输入故事大致内容，大模型生成完整故事，以及多个分镜头插画并展示。
要调用生图插件@图片生成与编辑（iRAG）​
```

# 迭代应用：LUI多轮对话修改
**应用的迭代是一个不断测试和优化的过程，我们可以通过“测试-分析-迭代”的思路，让秒哒不断优化应用内容。**

[流程图]
## **测试应用生成效果**
**💻测试目标：我们重点测试应用初次生成的功能完整性，找到问题，进行修改，达到核心功能可用。**

1. 我们先用一个query来测试一下应用的生成效果

输入query：

```
一个科考团队去西藏进行植物考察，偶然发现了圣地香巴拉的入口
```

## **效果分析**
🧐基于上述输入-输出结果，我们可以分析出以下4点问题：

1. 图片生成失败。需要优化成一个一个的生成图片，避免同时生成多个图片导致失败
2. 图片风格不是期望的风格。需要用户提前明确期望输出的风格，并保证图片输出一致性
3. 没有重新生成的功能。需要增加一个重新生成的按钮，如果生成效果不满意，支持重新生成结果
4. 生成故事时，没有loading状态。

## **应用迭代**
🚀根据上述效果分析，我们定位到4个需要修改的问题。

下面我们将通过多轮修改，**每次迭代只解决一个问题**，如此不断迭代应用，直至达到预期效果。

所有迭代的测试query，统一用同一个：

```
一个科考团队去西藏进行植物考察，偶然发现了圣地香巴拉的入口
```

# 总结
利用秒哒平台生成应用，有以下几个关键点：

1. 🎯明确自己的需求，并向大模型清晰表达出来。调用插件方面用@功能，能让应用生成效果更加准确。
2. 🙋分析应用问题，清晰列出自己想解决的问题点
3. 🚀一次迭代仅解决一个问题，避免一次性让大模型解决过多复杂问题，逐步迭代
4. 🎉最后检查应用效果，优化广场曝光的封面图及描述，完成上架
