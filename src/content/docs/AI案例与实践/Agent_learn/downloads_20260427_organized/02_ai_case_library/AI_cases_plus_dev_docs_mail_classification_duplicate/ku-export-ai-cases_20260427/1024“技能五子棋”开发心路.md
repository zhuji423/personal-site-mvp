1024“技能五子棋”开发心路

#### 🧑‍🏫 案例作者：[@童振宇](https://ku.baidu-int.com?t=mention&mt=contact&id=15ce5740-fce5-11f0-a7c0-19106d40e3c6)
#### 🎬 案例场景：开发
#### 🔧 使用工具：秒哒
#### 📒 案例概要：本文分享了在开发“技能五子棋”项目中，将AI作为核心设计伙伴的心路历程。通过与AI协作，诊断传统五子棋的缺陷，探索趣味性方向，生成并优化技能创意，最终构建出稳固且富有策略深度的游戏框架。AI在创意生成、逻辑推演和系统整合中发挥了关键作用，提升了开发效率和游戏质量。此外，还介绍了AI在视频低质量检测系统开发中的辅助作用，展示了AI在算法设计和代码实施中的多重价值。
## ​**AI作为核心设计伙伴：我的“技能五子棋”开发心路**
访问链接：[https://app-6z9xnv1i10qp.appmiaoda.com](https://app-6z9xnv1i10qp.appmiaoda.com)​

​**核心理念：​**​ 在“技能五子棋”项目中，我并未将AI视为一个简单的问答工具，而是将其定位为整个游戏机制设计的核心协作伙伴。我的目标是：与AI协同，将“创造一款更平衡、更具策略深度的五子棋游戏”这一愿景，系统性地转化为一个稳固、可玩、且充满趣味的最终设计方案。

[流程图]
### ​**第一步：问题诊断与趣味性探索——与AI共同定位核心缺陷与创新方向**​
* **我的提问（Prompt 1 - 诊断）：​**​ “请从游戏设计理论的角度，深入分析传统十五路五子棋存在哪些核心缺陷或局限性？请不止于平衡性，从规则深度、玩家心理、重复可玩性等多个维度进行分析。”
* ​**AI的诊断输出：​**​ AI反馈了多个关键点：

    1. ​**策略透明化与最优解倾向：​**​ 高手对弈易趋于公式化，开局阶段尤其如此，限制了创造性。
    2. ​**决策维度单一：​**​ 胜负完全依赖于“连子”这一单一目标，缺乏其他策略轴心，容易导致游戏后期枯燥。
    3. ​**互动性偏弱：​**​ 玩家互动主要体现在阻挡对方，缺乏更丰富的、能直接改变棋盘态势的交互手段。

* ​**我的提问（Prompt 2 - 探索）：​**​ “基于以上缺陷，我们可以从哪些方向入手，为五子棋注入新的‘趣味性’？请借鉴其他经典游戏（如棋类、卡牌游戏、电子游戏）中增加趣味性的核心设计理念，并提出一些大胆的设想。”
* ​**AI的创意启发：​**​ AI提出了几个方向，其中包括：
    * ​**引入“非对称能力”：​**​ 像《星际争霸》不同种族那样，为先后手玩家赋予不同的专属能力，从根本上改变博弈的动态。
    * ​**增加“资源管理”层：​**​ 引入类似技能点、行动点的概念，让玩家在每个回合面临“落子”还是“使用技能”的策略抉择。
    * ​**创造“瞬时效应”与“心理博弈”：​**​ 加入能产生一次性强大效果或欺骗对手的机制，增加对局的戏剧性和不确定性。

* ​**我的决策与心得：​**​ 这一步至关重要。AI的作用像一个**知识渊博的设计顾问**，它帮助我将模糊的“让游戏更好玩”的直觉，系统化地梳理成了明确的“设计切入点”。我们共同得出的结论是：​**通过引入“非对称技能系统”来增加决策维度、增强玩家互动，是解决传统五子棋缺陷、提升趣味性的最有效路径。​**​ 这为后续所有的具体设计奠定了坚实的理论和方向基础。



### **第二步：创意生成与逻辑推演——借助AI进行“技能”的头脑风暴与可行性分析**​
在明确“非对称技能”这个主方向后，工作重点转向生成具体技能创意，并评估其与核心玩法的兼容性。

* ​**AI的协作过程：​**​
    * ​**我的提问（Prompt）：​**​ “现在，请围绕‘非对称技能’这个方向进行具体构思。请为后手方设计一些能有效补偿其劣势、偏向‘防御反击’和‘节奏控制’的技能；为先手方设计一些能发挥其先动优势、但更偏向‘布局’与‘控制’而非单纯进攻的技能。同时，再设计一些双方均可使用、能增加变数和心理博弈的‘通用技能’。每个技能需描述其效果，并分析其将如何影响对局策略。”
    * ​**AI的创意输出与我的筛选：​**​ AI生成了大量创意，我从中筛选并优化，形成了您文档中的技能体系。例如：
        * ​**后手专属技能【以守为攻】【后发先至】​**​：AI在分析时指出，这类技能的本质是赋予后手“节奏调控”能力，通过牺牲一回合的落子权来换取棋盘状态的瞬时巨大改变，是强有力的补偿手段。
        * ​**先手专属技能【星移】【点禁】​**​：AI帮助我认识到，为先手设计技能不应放大其先攻优势，而应引导向“布局与控制”。【点禁】技能完美体现了“机制制约”的目标，而【星移】则增加了先手布局的灵活性而非单纯攻击力。
        * ​**通用技能【阴阳转换】【诡计惑众】​**​：AI特别强调，这类技能是“增加心理博弈”的关键，它们引入了不确定性，使游戏超越了单纯的计算，提升了趣味深度。

    * ​**逻辑推演Prompt：​**​ “请针对【诡计惑众】技能，推演其可能出现的滥用情况及对策。例如，如何防止玩家用假棋子完全封锁关键点？”

* ​**我的决策与心得：​**​ AI在此阶段是一个无穷尽的创意喷泉和严格的逻辑检验员。它不仅能提供点子，更能从设计原理层面分析技能的影响，帮助我预见到潜在问题，从而在设计阶段就加入使用限制（如跳过回合、持续回合数）。



### **第三步：系统整合与规则细化——与AI共同构建稳固的游戏框架**​
当技能点子确定后，最大的挑战是如何将它们有机地整合到标准的五子棋回合框架中，形成自洽、无歧义的完整规则。

* ​**AI的协作过程：​**​
    * ​**我的提问（Prompt）：​**​ “现在需要将上述所有技能整合进标准的五子棋回合制流程中。请帮我定义一个清晰的游戏状态机。重点说明：1. 技能在回合的哪个阶段被声明和使用？2. 像【以守为攻】这种‘跳过回合’的技能，如何影响回合计数和先后手顺序？3. 【点禁】技能的持续回合‘双方合计3回合’，其具体的状态应如何记录和更新？”
    * ​**AI的框架构建支持：​**​ AI以伪代码和状态流的形式，帮我勾勒出清晰的规则，确保了设计的严谨性。

* ​**我的决策与心得：​**​ 此阶段，AI扮演了**一名不知疲倦的规则律师和系统分析师**。它帮助我将独立的技能创意，系统地编织成一个逻辑严密、没有漏洞的规则体系，确保了最终设计成果的稳固性和可实施性。

## ​**AI协同的算法工程实践：构建视频低质量检测系统的完整历程**
背景：通过基于策略和模型的方法，对低质量的视频进行检测

思路：在这个项目的实施过程中，我首先通过AI来​对常见视频的低质量问题进行了总结、分类、探究了背后的原因、可能解决方案，在这一部分使用了AI的联网功能和相关学术论文的agent功能，之后通过AI对已有的方案进行写代码debug的过程，最后多次迭代后应该算法。

**AI对于算法顶层设计的帮助：**对于算法的顶层设计而言，AI可以帮我从一个模糊、抽象的需求(如优化视频的检测效率)转化成若干具体的业务内容，以及可能需要的算法目标如“降低码率”、“提升主观质量”、“减少计算复杂度”），之后再根据目标转化成对应的算法（如“传统变换编码”、“基于深度学习的内环滤波”、“自适应量化参数选择”）；但是不同情况下的问题解决方案都是不同，AI可以根据当前的具体条件（如“实时性要求高”、“硬件资源有限”)分析优缺点，进行一个“头脑风暴”，最后构建一个稳固的算法逻辑框架

**AI对于代码细节的帮助：**对于代码实施而言， AI是的“代码实施加速器”和“细节纠正器”，可以用自然语言描述函数功能，之后快速生成高质量的基础代码结构，避免重复造轮子，对于复杂算法，让AI提供多种实现版本并进行解释，可以根据不同条件进行初步优化（如循环展开、内存对齐提示），最后，我们可以将出错的代码段和报错信息抛给AI，它能快速定位潜在问题，并提供修复建议，扮演一个不知疲倦的初级代码审查员。

[流程图]


#### ​**第一阶段：攻克核心难题——从模糊需求到可执行技术方案**​
项目伊始，我们面临的唯一输入是一个极其模糊的业务目标：“自动检测出视频中的低质量片段”。这只是一个方向，而非可执行的任务。第一个工程挑战就是将其转化为一个定义清晰、边界明确的技术问题。

**需求分析：**我的首要行动是与AI共同启动一个“需求分析会”。以一个技术伙伴的身份向它提问：“我们需要共同定义‘视频低质量’。请从工程视角出发，系统性地列出常见的低质类型、其典型的视觉表现，并推测其背后的技术成因。”这次交互的价值立刻显现。AI没有给出模糊的答案，而是提供了一个结构化的列表：​**1) 内容模糊与抖动**，成因可能在于对焦失败、手持不稳或编解码失真；**2) 块效应与噪声**，通常源于过度压缩或低码率编码；**3) 色彩与亮度异常**，如曝光不足或白平衡错误；**4) 时序上的不连贯**，如帧重复、帧丢失或非正常快速切换。

**可行的技术路径：**这一输出彻底改变了问题性质。我们将“低质量”概念，具体化为四个可被独立检测的技术指标。这确保了后续技术方案的设计能够全面覆盖业务方可能关心的各种情况，避免了后期因需求遗漏导致的返工。在明确要解决哪些子问题后，我们进入了技术方案的“头脑风暴”阶段。此时，项目的关键约束条件被引入讨论：实时性要求较高、初期没有任何标注数据、计算资源相对有限。我向AI清晰地描述了这些约束，并提问：“基于我们刚才定义的四类低质问题，在给定的约束条件下，有哪些可行的技术路径？请分别阐述其原理、优缺点以及在当前场景下的适用性。”

AI的回应是一个丰富的、带有权衡分析的技术选项菜单。它提到了端到端的深度学习模型，但立即指出其在无数据、高算力需求下的不适用性，我们共同否决了这条路径。它重点推荐了几种轻量级方案：​**对于检测重复帧和画面静默，感知哈希（尤其是pHash和dHash）是近乎完美的选择**，它们计算效率极高，且对图片的微小变形不敏感；**对于分析抖动和异常运动，光流法**能够精准捕捉帧与帧之间像素点的运动矢量，通过分析运动场的统计特征（如方差）即可有效识别不稳定画面；**作为补充，传统的图像统计特征**，如计算拉普拉斯算子方差来衡量图像清晰度，是实现简单、计算开销极低的方案，可用于检测静态的模糊。

**方法的选择：**基于这次深入的探讨，一个清晰的最优策略浮出水面：​**采用多策略融合的方案，而非寻求单一的算法。​**​ 这个决策充满了工程上的权衡智慧：放弃追求理论上限最高的复杂模型，选择一组可解释性强、计算轻量、并能针对特定问题的方法进行组合。这不仅满足了项目的初始约束，还为我们未来的迭代留出了清晰路径——当前各轻量检测器的输出结果，在未来可以轻松地作为特征，输入到一个更复杂的分类器（如XGBoost）中进行最终决策。

至此，在AI的辅助下，一个稳固的系统架构蓝图被绘制出来。整个处理流水线被设计为几个核心模块：首先，一个**关键帧提取模块**，利用感知哈希进行场景切换检测，将视频分解为连续的镜头，并选取代表性帧进行处理，从而极大降低计算负荷；随后，​**帧内质量检测模块**在关键帧上并行计算其哈希值和清晰度，以发现重复帧和静态模糊；同时，​**帧间质量检测模块**在镜头内选取短帧序列，计算光流并分析其运动一致性，以捕捉抖动问题；最后，一个**决策融合模块**负责设定阈值规则，综合所有检测器的证据，给出最终的低质概率判断。这个架构层次分明，模块间耦合度低，具备了良好的可测试性和可扩展性。

#### ​**第二阶段：高效实施——将蓝图转化为可靠代码**​
有了坚实的设计，开发工作进入代码实施阶段。AI的角色也从设计顾问无缝切换为效率倍增器。

在这个阶段，AI的首要价值体现在**快速生成高质量的基础代码模块**。我不再需要从零开始编写诸如“计算光流”或“计算感知哈希”这样的标准函数。取而代之的是，使用精确的自然语言向AI描述需求。例如，我会输入：“使用Python和OpenCV，编写一个函数来计算两帧图像之间的Farneback稠密光流。函数应返回运动矢量的平均幅度和整体方差，并包含基本的输入验证。”AI在秒级内就能返回结构清晰、注释完备、甚至包含了基本异常处理的代码片段。这使我能将精力完全集中在核心业务逻辑的串联、算法参数的调优以及系统集成的关键工作上，而非重复实现基础功能。

当系统集成过程中不可避免地遇到错误时，AI又成为了我身边**不知疲倦的调试助手**。工程师都深知，调试过程往往占据大量开发时间。现在，当出现异常时，我可以直接将错误的堆栈跟踪信息和相关的代码片段直接抛给AI。例如，遇到一个`NoneType has no attribute 'shape'`的错误，AI能立刻分析出是`cv2.imread`读取图像失败所致，并建议添加空值检查。这种交互模式极大地缩短了定位问题所需的时间，仿佛拥有一位随时待命、知识渊博的初级工程师协助进行代码审查和故障排查。

此外，在性能优化方面，AI也能提供**有价值的咨询建议**。当发现光流计算成为性能瓶颈时，我可以向其咨询优化思路。AI会给出诸如“考虑将图像缩放至原尺寸的50%再进行光流计算”、“评估使用稀疏光流算法（如Lucas-Kanade）是否满足精度要求”或“检查OpenCV是否编译了GPU加速支持”等具体、可实施的建议。这些建议为深度优化提供了明确的切入点和方向。

#### ​**总结与反思：构建高效人机协同工作流的关键**​
通过“视频低质量检测”项目的完整实践，我深刻体会到，将AI深度融入开发流程，其价值远超简单的代码自动补全。它构建了一种全新的人机协同工作模式。要最大化这种模式的效益，几个关键点至关重要：

首要的是**精准定义问题的能力**。向AI提问的质量直接决定了回答的质量。模糊的问题得到的是泛泛而谈，而具体、包含上下文和约束条件的问题，才能引导AI给出有工程价值的答案。

核心在于**工程师始终保持决策主导权**。AI是理想的参谋，但它不是统帅。它提供的方案、代码都必须经过工程师严格的审视、测试和验证。我的角色是利用专业判断力，对AI的输出进行筛选、评估和决策，这是项目成功的根本保证。

最后，这是一个**迭代式、螺旋上升的协同过程**。最有效的模式并非一次性问答，而是“提出构想 -> AI扩展与补充 -> 工程师批判性验证并深化思考 -> 提出更精准的新问题”的快速循环。整个视频低质量检测系统的设计，正是在多轮这样的循环中，从模糊一步步走向清晰、稳健和可执行。

​**结论是，AI还无法替代算法工程师，但它已经深刻地重塑了算法工程师的工作方式。​**​ 通过将AI作为战略与战术层面的协同伙伴，我们可以更高效地应对不确定性，更稳健地完成技术决策，更快速地将想法转化为可靠的代码。这种深度融合，标志着算法工程开发范式的一次重要演进。掌握并优化这一协同工作流，已成为提升工程师个人和团队效能的关键。
