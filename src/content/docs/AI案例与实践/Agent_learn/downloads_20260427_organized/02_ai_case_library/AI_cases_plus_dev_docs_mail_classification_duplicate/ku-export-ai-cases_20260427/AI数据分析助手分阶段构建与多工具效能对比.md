# **项目阶段总览（Summary）**
本项目共分为**三个阶段**，完整记录了从需求调研到产品落地的AI辅助开发全流程：

|阶段|阶段名称|使用AI工具|核心任务|产出成果|

#### **测试方法**

#### **测试结果对比**
|**功能模块**|**秒哒**|**Gemini**|
|-|-|-|
|**用户注册**|✅ 正常实现|❌ 无法实现|
|**数据上传**|✅ 支持Excel/CSV|✅ 支持Excel/CSV|

#### **初步发现**
**秒哒优势**：用户注册流程完善，数据上传格式支持全面，知识库前端展示正常

**共性短板**：学术报告下载功能均未完善实现



# 三、第二轮测试：系统性错误修复
#### **测试目标**
评估两款工具对系统错误的**自动识别能力**、**修复效率**和**指令理解准确度**。



#### **秒哒的修改过程与问题**
（1）假数据生成问题

    * 指令要求："根据用户上传数据进行数据分析"
    * 实际表现：**生成假数据而非分析真实上传数据**
    * 后续修改后，界面显示"此为模拟数据"提示，存在**误导性**

![假数据生成：上传数据集只有性别与身高两个变量的情况下，分析解读出现年龄和满意度](/personal-site-mvp/img/doc-placeholder.svg "假数据生成：上传数据集只有性别与身高两个变量的情况下，分析解读出现年龄和满意度")
（2）Excel识别失败

    * 指令要求："识别Excel数据并进行分析"
    * 实际表现：**无法正确解析Excel文件内容**，数据呈现错误

（3）侧边栏状态异常

    * 指令要求："侧边栏在上传数据和查看数据分析结果的时候默认收起"
    * 实际表现：**切换界面后依旧默认弹出**，需反复手动收回

（4）指令回馈异常

    * 额外系统性修改需要消耗"秒点"（平台计费单位）
    * 指令回馈存在异常，理解成本高

（5）数据分析表面化

    * 仅有数据呈现，缺乏深度分析能力

![数据分析片面化：分析用户上传数据集后，只是简单呈现数据结果](/personal-site-mvp/img/doc-placeholder.svg "数据分析片面化：分析用户上传数据集后，只是简单呈现数据结果")


#### **Gemini的修改过程与表现**
**优势表现**：

（1）清晰的错误识别

    * 可自动识别系统错误，但**单次只聚焦一个错误**
    * **指令回馈清晰明确**，可以理解全部内容

（2）友好的调试提示

    * 系统自动提示错误原因（如：图像长宽设置为-1）
    * 便于后期针对性修改

**存在的不足**：

* 多个系统性错误需**反复识别、反复修改**
* 个别数据分析无法生成图像
* 部分图像生成时报错



#### **对比总结**
|维度|秒哒|Gemini|
|-|-|-|
|自动修复|可自动识别，不消耗秒点|可自动识别，单次处理一个|
|指令理解|❌ 回馈异常，易产生误导|✅ 清晰明确，执行精准|
|调试友好性|❌ 需大量人工干预|✅ 错误提示详细，便于调试|
|数据真实性|❌ **生成假数据，严重失信**|✅ 基于真实数据分析|
|修改成本|额外修改消耗秒点|无额外计费压力|

# 四、第三轮测试：数据可视化优化
#### **测试目标**
评估两款工具在图像生成、回归拟合、数据排序等方面的表现



#### **秒哒的数据排序问题**
![秒哒生成的图表，横坐标按原始数据顺序排列，显得混乱无序](/personal-site-mvp/img/doc-placeholder.svg "秒哒生成的图表，横坐标按原始数据顺序排列，显得混乱无序")
核心问题：无法按数值大小排序

* 图表横坐标**不按数据从小到大展示**
* 而是按数据在**上传表格中出现的先后顺序排列**
* 严重影响数据可视化的专业性和可读性

调整指令：“数据图表横纵坐标轴数据都要按从小到大排列，不能乱序排列。”

![调整后结果](/personal-site-mvp/img/doc-placeholder.svg "调整后结果")


#### **Gemini的图像调整过程**
调整前的问题：

* 图像生成报错（长宽设置为-1）

![](/personal-site-mvp/img/doc-placeholder.svg "")
调整步骤：

（1）根据系统提示识别错误原因

（2）修改图像参数配置

（3）重新生成并验证

调整后结果：

* ✅ 成功生成散点图
* ✅ 数据解读准确
* ✅ 可视化效果专业

![](/personal-site-mvp/img/doc-placeholder.svg "")


#### 关键洞察：
数据可视化不仅是"画出图表"，更需要**合理的排序逻辑**和**准确的变量理解**。Gemini在这方面的优势使其生成的分析报告更具专业性，而秒哒的不足需要大量人工干预。

# 五、第四轮测试：深度数据分析能力
#### **变量理解与语义识别**
**秒哒的局限：**

* ❌ **无法识别变量名称的具体含义**
* 只能进行简单的关系分析和结果呈现
* 缺乏对业务语义的理解

![秒哒的数据分析结果截图，仅有数值关系，无变量含义解释](/personal-site-mvp/img/doc-placeholder.svg "秒哒的数据分析结果截图，仅有数值关系，无变量含义解释")
**Gemini的优势**：

* ✅ 系统中**接入了AI大模型**
* ✅ 可**识别数据集中变量的业务含义**
* ✅ 给予**专业的变量解释和数据分析说明**

![Gemini的数据分析结果截图，能识别celebrity_age_during_season是年龄，placement代表排名，并猜测数据背景是比赛](/personal-site-mvp/img/doc-placeholder.svg "Gemini的数据分析结果截图，能识别celebrity_age_during_season是年龄，placement代表排名，并猜测数据背景是比赛")


#### **文字说明深度对比**
|对比项|秒哒|Gemini|
|-|-|-|
|变量含义识别|❌ 无法识别|✅ 精准识别|
|业务语义理解|❌ 表面化|✅ 深度理解|
|分析说明质量|❌ 仅有数据呈现|✅ 专业解读|
|学术价值|低|高|

# 六、指令理解与智能建议对比
#### **指令复杂程度需求**
秒哒：高指令复杂度需求

* 需要**比Gemini更多、更详细的指令**才能调整出效果
* 最终结果**仍比Gemini差**

|简单指令|秒哒表现|Gemini表现|
|-|-|-|
|"生成图表"|❌ 横坐标混乱无序|✅ 自动合理排序|
|"数据分析"|❌ 不分析上传表格，生成假结果|✅ 基于真实数据深度分析|

秒哒的指令理解能力有限，需要用户具备较强的**提示词工程能力**。



#### **智能建议能力**
**Gemini的主动智能**：

* 会为程序**自动提供智能建议**
* 示例："是否需要加入假设检验？"
* 展现出更强的**业务理解能力**和**开发辅助能力**

![](/personal-site-mvp/img/doc-placeholder.svg "")


#### **Gemini的稳定性问题**
**发现的缺陷**：

* 在修改程序时，会把**之前已调试好的界面又改回最初状态**
* 例如：知识库部分已调试完成，修改其他功能时又被重置

**口令补充提示：**

“在保留XXX不变的基础上，增加/改变......"

# 七、核心差异总结及选型建议
#### **功能实现对比总结表**
|功能维度|秒哒|Gemini|胜出方|
|-|-|-|-|
|用户系统|✅ 完善|❌ 缺失|秒哒|
|数据上传|✅ 格式支持全|✅ 稳定|平手|
|数据分析|❌ 假数据|✅ 真实深度分析|Gemini|
|可视化排序|❌ 乱序|✅ 有序|Gemini|
|变量理解|❌ 无语义|✅ AI大模型识别|Gemini|
|智能建议|❌ 无|✅ 主动提供|Gemini|
|错误提示|❌ 误导|✅ 清晰|Gemini|
|界面稳定性|⚠️ 侧边栏异常|⚠️ 修改时重置|各有不足|



#### **使用场景建议**
**选择Gemini的场景**：

* 深度数据分析需求
* 学术研究、数据科学项目
* 需要专业数据解读的业务分析
* 复杂数据可视化需求

**选择秒哒的场景**：

* 快速原型开发
* 基础用户系统搭建
* 简单数据展示需求
* 对开发效率要求高于分析深度
