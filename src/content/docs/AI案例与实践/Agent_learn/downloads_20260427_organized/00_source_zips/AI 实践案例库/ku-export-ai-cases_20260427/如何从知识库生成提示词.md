# fcstorage新增层级37 agent完整上线流程

## 文档说明
本文档基于知识库文档jCHB6NJSxXqSdE和OsDqSjjvKebh6N，详细记录fcstorage新增层级37 agent的完整开发、联调、上线流程。

**需求类型**：需求类型二 - 字段在业务端已存在，DAS已下发，Databus APP层、BS需要新增字段

**涉及团队**：
- RD（开发人员）
- DAS团队
- Databus团队
- BSS团队
- QA团队

## 开发阶段

### 1. 明确需求
**负责人**：RD

**操作步骤**：
1. 联系DAS团队更新广告数据流字段接口文档
2. 确认以下内容：
   - 层级名称与层级ID关系（参考`baidu/im-data/proto-desc:level_def.ini`）
   - 层级字段定义
   - 去重key和分库key
   - 字段格式符合广告流新增字段要求

**关键要求**：
- 所有产品线、所有数据流共享层级ID，不允许与现有重复
- 新增层级ID建议从39及以后开始
- 删除增量仅下发搜索必要的字段，而不是全部字段

### 2. 更新全局描述proto
**负责人**：RD

**操作步骤**：
1. 访问`baidu/im-data/proto-desc`仓库
2. 在`level_def.ini`中定义层级名称和层级ID
3. 在对应流的proto描述文件中引入新层级，配置要求：
   - 新增层级必须配置在`message Flow`中，字段序号为层级ID
   - 若不需要分库，需增加到`message FlowUnshard`中

  
### 3. 平台生成代码
**负责人**：RD

#### 3.1 更新D平台数据类型proto
- 代码库：`baidu/im-data/databus-proto`仓库
- 操作：
   1. D平台下游数据：在 AutoBS平台 找到 fcstorage 模块，确定对应的 PS平台对应的下游数据，从而推导出对应的 D平台对应的下游数据 （PS数据类型_D）
   2. 修改D数据类型：**只更新**D平台下游数据的 `data.proto`，添加字段（序号必须与全局描述proto一致）
- 发起CR（暂时不合并），CR comments包含BS开发的icafe卡片ID
- 提醒“等待databus-proto RB拉出”**
  - 每日晚8点自动拉 RB
  - 在 Databus 平台“类型管理”中，更新 D平台下游数据 的proto版本
  - 点击“生效”

#### 3.2 生成BS代码
**BSS平台操作**：
1. 登录BSS平台，找到fcstorage相关模块
2. **层级配置**：
   - 点击"编辑"
   - 选择需要修改的层级
   - 勾选新增的层级37 agent字段
3. **表配置**：
   - 在对应表中勾选所需字段
   - 若需要自定义字段，在"自定义字段配置"中添加
4. **AQL配置**：
   - 设置SELECT语句（声明要返回的字段）
   - 配置tags布尔过滤表达式
5. **生成CR**：按顺序生成并合并CR

### 4. 自定义代码开发（可选）
**负责人**：RD

**适用场景**：
- 复杂建库逻辑（自定义字段解析等特殊逻辑）
- 复杂查询逻辑（AQL无法表达的过滤、排序等）

**代码位置**：common目录下
**要求**：任何涉及自定义代码的开发都必须写CTS

## 相关平台

通过autobs mcp，获取 autobs平台信息，覆盖如下核心概念：
应用方面：
- 检索应用：app，代表可部署到线上的检索服务，部署后成为数据订阅者“模块”
- 平台：platform，一个模块/检索应用有多平台
- 数据层级：level
- 数据表：Table，支持ssd表格
- 检索语句：AQL（Ads SQL），声明驼峰（如`FcWinfoSeek`）会生成全大写的（如`FC_WINFO_SEEK`） 
数据流方面：
- 模块：module，代表数据订阅者，订阅下游数据
- 下游数据：apptask，某模块在某平台订阅的数据名。内部包含：基准snapshot、增量stream
- 数据和数据类型：数据被订阅，数据背后可能共享相同的数据类型
**重要**：
① 注意区分”模块“和”检索应用“，用模块查看数据流，用检索应用编码表&AQL。比如`fcstorage`作为模块和检索应用，不仅id不同、detail也不同。
