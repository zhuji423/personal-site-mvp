# 一、业务背景及问题分析
**推荐业务策略迭代频繁、需求吞吐高，虽然AI研发交付智能体提升了无人值守交付率，但需要QA人工介入的需求和问题仍然很多，QA人力消耗仍然居高不下。**

推荐技术业务从2023年底开始探索研发交付智能体建设，通过大模型的「洞察、规划、执行、决策」能力，直接将「无风险需求」或「AI生成case+自动化执行后」转化为无风险的需求，交由AIQA完成交付，实现了项目全流程无人值守交付上线。时至今日，推荐技术业务方向无人值守率已经达到70%+，在项目迭代过程中，人工QA主要通过值班制支持开发团队，包括**处理流水线问题**、**解答流程相关疑问**、以及**参与项目发布的准出决策**等等。由于推荐策略迭代频繁、需求吞吐量大，即使在值班模式下，仍需投入大量人力进行全程跟进，导致人力成本持续处于高位。下图所示，是从人耗情况，以及人耗分布两个角度，对值班人力消耗进行的分析。

**存在问题：应用的知识经验老旧、缺失，回答问题时，内容往往过于陈旧，或不符合现状实情、或根本无法回答用户提出的问题。**

**存在问题：定位结论、提供的解决方案刻板呆滞，对于超出预设范围的问题，无法自主学习、灵活运用知识和工具自主的辅助用户定位完成问题修复。**

**存在问题：只能给出执行现状、准入报告，缺少经验积累和决策思路，无法自主与RD沟通获取决策依据，也无法自主决策项目准出风险，强依赖人工。**

回顾上述建设方案，我们在积累沉淀知识、挖掘模型参考的思考经验、建设Agent MCP工具时，往往会先搜集历史沉淀下来的各类经验文档（包括但不限于业务知识、流程规范、交付常识等）作为知识输入喂给模型，对于没有积累的部分则依靠人工梳理知识文档和总结，**这种知识收集、积累与沉淀的方式，其核心问题如下：**

**1.知识梳理强依赖人、更新滞后、维护成本极高**

经验文档的及时更新，十分依赖人的主观能动性，在业务高速迭代、知识快速更新的情况下，维护一个好的时效性高文档，至少需要天/周级更新，而每次更新至少需要耗费半小时-1小时，维护成本极高。然而即使真的做到每周更新，在某些场景下，仍无法满足实时性的要求，比如突发底层依赖重大故障时，以往的处理经验不起作用，必须等待依赖方修复时，无论是天级还是周级的知识更新，都无法做到及时更正数字员工的知识储备。

**2.人人之间经验难以共享和传承，私聊沟通产生信息孤岛**

开发向值班咨询求助时，往往是1v1私聊模式，值班期间各自积累的经验难以共享，即使在核心群聊中进行咨询，人工值班也很难时刻关注和学习大家的处理经验，缺少经验的新同学在值班初期往往会摸不到头脑。另外，人工QA同学通常负责维护不同的工具，彼此有自己更需熟悉的领域，这些长时间积累下的经验都很难处处落实到文字和文档中，往往都在值班过程中不经意和无意识流露。

**3.未及时迭代的经验价值随时间流逝而逐渐降低**

人工沉淀的知识、经验的价值，如果没有及时更新迭代，则会随着时间流逝而逐渐减低，即产生知识衰减。例如：有较大调整时，技术框架、开发经验、流程规范等均有更新。测试工具迁移cnap后，测试环境登陆方法大不相同、问题定位思路都需要重新梳理等。

综上所述，知识文档场景知识经验的陈旧与匮乏，是制约Agent能力达成的核心瓶颈。为此，**我们亟需构建一个实时、精准、高效的「知识飞轮」系统，**为其提供持续、优质的知识供给，以驱动Agent能力实现突破，从而为Feed AIQA数字员工「MEG智能交付助手」的进化提供坚实基础。

**那这些「实时」、「精准」、「高效」的知识从何而来，又怎么能够让飞轮真正的转起来呢？**

随着大模型和Agent技术蓬勃发展，自主规划、调用工具、自我反思的能力日益增强，我们开始思考：**值班与RD****沟通的过程、对话的内容、问题解决的思路****，理论上就是****最新、最正确的知识，这部分知识也是最重要最有价值的资产****。那么AI员工可否通过****持续自主****学习真人值班员工脑中的知识和思考方式****，内化为自己的思考模式和知识体系，主动协助真人解决问题，提升值班答疑效率，从而提升交付效能呢？**

# 二、解决方案
基于以上思考，我们开始尝试根据大家在值班过程中的沟通记录沉淀值班员工的**思考方式和问答经验**，将其应用于Feed AIQA数字员工的各类Agent中，使其在处理RD问题时可以应用到更可靠、更及时、更全面的知识内容。

以此为目标，我们建设了一套**基于群沟通记录的知识数据飞轮机制**，在整体运转机制中引入两个AIQA数字员工角色：

    1. **AIQA知识构建员工-「见闻蹊」，**作为**观察者、学习者、沉淀者，**在群内“默默倾听”，负责知识的及时萃取与沉淀。
    2. **AIQA交付值班员工-「MEG智能交付助手」，**作为**执行者、服务者、应用者，**利用**「见闻蹊」**的沉淀总结，调用工具，协助答疑。

[流程图]
为打造一个可持续运转、越用越强的智能系统，我们以“知识飞轮”为核心，设计了一个从场景构建到闭环进化的完整建设路径。其核心思路在于，将每一次值班沟通的服务交互，都转化为驱动系统智能增长的燃料。基于Feed推荐技术业务的知识飞轮建设思路如下：

建设值班工单群模式

打破信息孤岛，方便数据沉淀

智能归档值班经验，动态更新知识体系

抵抗知识衰减曲线，降低对人的依赖

主动感知用户问题，提供解决方案

收集评估反馈，实现自我纠偏与修正

#### **2.1 改变沟通场所：私域->公域 —— 合理合法的收集用户与值班的沟通过程**
为实现服务过程的知识沉淀与效能提升，我们以AIQA数字员工「MEG智能交付助手」为交互入口，建设了全新的值班客服机制。在新的值班客服机制下，值班QA与RD在工单群内进行沟通，AIQA会实时监测RD问题，在适当时机主动与RD沟通互动、答疑解惑、调用工具、推进流程。整体机制上存在的变化如下：

* **沟通场域：从私聊到工单群公域沟通，**建立工单群作为公共沟通场域。值班客服可直接邀请相关负责同事入群协同处理，所有群内成员（人/AI）均可观摩学习，实现经验共享。
* **服务模式：从被动等待到主动猜想，**数字员工在创建工单群后，会主动调用推荐服务工具，基于用户画像、RD开发行为、历史行为与对话记忆，主动猜想并推荐用户可能想问的问题。
* **响应时效：从延迟等待到秒级应答，**数字员工在群内实时待命，对能力范围内的问题立即响应。人工值班员可随时对回答进行补充或纠正。
* **知识沉淀：从直接流失到自动收集，**公域沟通模式为知识沉淀创造了条件。数字员工可持续在群内收集对话数据，自动挖掘与沉淀高价值内容。

#### 2.2 知识动态沉淀 —— 如何将对话沟通过程转化为知识和经验
知识收集的场景不局限于值班功能，其他输出知识的各类群聊例如需求沟通、问题排查、线上问题跟进、核心答疑等均可以用于收集沉淀不同应用的知识。知识动态沉淀的整体方案如下所示：

* **知识沉淀**：
    * 首先，系统对沟通消息流中的多模态数据进行语义理解，挖掘出其中的核心信息、情感信息、背景知识、对话链路等；
    * 然后基于对话特征、时间窗口以及一定规则划分出在讨论同一主题的对话链路；
    * 最后基于同一主题的对话链路，依据不同的应用背景和知识目标，调用不同的Prompt让大模型协助沉淀问答知识对、解决问题的思考方式(COT)，以及推荐可以建设的工具等。

* **画像沉淀**：根据用户、群组、人类/数字员工的基础信息和对话记录，抽象出各维度的画像特征，包括但不限于用户角色、入职时常、行为偏好、业务归属，群组的业务属性、功能属性、近期热点等，员工的能力倾向、对话特色等。
* **知识评估反馈**：对于在对话过程中沉淀下来的知识，首先通过引入自动化评估模型，过滤闲聊类对话内容，根据其不同的用途定义交付知识类别，对其进行归类与评估，对知识的价值进行打分，沉淀出可利用的高价值知识内容。

#### 2.3 知识应用与反馈飞轮
目前，推荐技术在值班场景沉淀出的知识，主要应用在数字员工面对**静态问答**和**自主思考类问答**两类场景中，并且在以上两种场景中，建设了完整的评估&反馈机制，收集高价值知识，使知识数据飞轮可以自行运转。

* **实现知识的动态保鲜：**通过建设实时更新的动态知识库，并应用RAG技术进行精准检索与回答，确保AIQA的每一次回复都基于最新、最准的信息。
* **协助复杂场景的自主处置：**通过融合思维链推理与自主Agent框架，并借助大模型分析沟通对话过程，输出相关建议来优化推理思维过程与MCP工具，使AIQA能在交付问答中主动理解、交互并解决用户问题。
* **实现能力的持续进化：**构建无缝融入工作流程的多渠道反馈体系，从对话交互中的轻量评价到定期的深度标注复盘，例如侧边栏、交互按钮、标注平台等多渠道，系统化收集人工评估与反馈，这些持续不断的人工评估与纠正，形成了“应用-反馈-优化”的高效闭环，使AIQA系统具备了自我迭代的能力，其表现将随着时间与交互的积累而不断精进。

# 四、后续展望
优质和丰富的数据知识是打造一个优秀的AIQA数字员工的基础，因此建设更加体系化的知识沉淀与价值评估体系是重中之重。

扩展更多的知识来源：目前只应用在值班工单群场景，后续可扩展到问题排查与定位、需求沟通等众多沟通场景，捕捉更多人类成员的思考过程；引入更多的知识维度，更好的理解对话过程，比如高质量文档，业务知识图谱等。

建设更有趣和高效的知识评估方式：人工评估引入激励与参与机制，激发大家的反馈兴趣；尝试根据评估人员的画像特征，增加知识权重配比等，使知识价值有更加良性的体现。引入更多的模型自动化评估方法，提升评估效率。

探索更丰富的知识应用场景：从更多维度系统化的构建沉淀出的知识形式，赋能业务基础知识、图谱关系知识、需求设计与开发指导等更多的应用场景。
