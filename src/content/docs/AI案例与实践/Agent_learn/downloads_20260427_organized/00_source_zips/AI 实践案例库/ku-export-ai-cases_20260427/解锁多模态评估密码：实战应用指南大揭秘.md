# 主题一：网盘扫描业务场景评测探索与实践——李冰
# 一、背景
### 1、业务介绍
网盘APP中有很多扫描业务，功能涵盖文件扫描、文字识别、图像处理、翻译、格式转换等功能于一体的智能扫描，支持用户拍照或导入文档&图片，并可生成图片、PDF、Office。扫描功能智能且高效，快速将线下文件转换为电子文档。

* 【拍照扫描】通过拍照并扫描处理，快速的将将纸质文档电子化，解决重要文件易丢、不易找、不易携带等问题，您可以对图像进行全方位的处理，比如图像矫正、文字识别、提亮、加水印、去手写等，生成超清电子版文档。
* 【图片加工】将图片中的内容识别出来，并一键转为Word文档，当您需要将一些线下屏幕、黑板中的内容转成可以随时查阅的电子文档时，就可以使用该功能。当文件限定使用途径、或者需要版权保护时，可以使用添加水印的功能来实现，您可以自定义水印的文字内容。以及还有将图片一键转化成高清PDF文档等功能。
* 【格式转换】支持用户将多个PDF文档合并成为一个PDF文档，或者将一个PDF文档中的部分页面提取出来，生成一个新的PDF文档。以及支持PDF转Office、Office转PDF各类型文件之间的互相转换。
* 【学习必备】用户拍摄试卷或者题目可以进行AI解答或批改记录错题本，支持图片等格式的文件进行翻译等学习场景。

### 2、目的
扫描业务覆盖场景很多，每个场景都有其特点和要求，需要根据具体情况定制化制定评测方案。因此对于扫描业务的评测方案，需要考虑各维度的质量效果，这样才能更好地满足用户的需求，提供更优质的服务。

# 二、评估方案
评估的核心目标是全面衡量大语言模型在遵循用户指令、执行指定图片理解任务时的综合能力，具体涵盖两个关键维度：一是对图片信息的获取能力，二是基于所获信息完成任务的执行能力。方案需要通过科学方法，力求客观、一致地评价模型的图片理解水平，最终满足实际业务中的用户需求。

由于评估需实现问题颗粒度的精细划分，并明确差异化的评估维度与清晰的评估标准，因此方案主要从以下两个层面展开设计：

### 1、推理结果打分机制
在实践中，方案采用了一套基于传统 GSB 机制升级而来的打分机制。该机制能更细粒度地反映模型的实际表现，而样本集评测分值的统计结果，也将作为衡量模型升级效果的核心参考依据。分值满意度概念如下：

|**0 分**完全不可用|**1 分**基本不可用|**2 分**部分可用|**3 分**完全可用|**4 分**完全可用且有亮点|
|-|-|-|-|-|

* **满意度**：采用0，1，2，3，4分进行评估，每道题都是以**3分的标准**扣分或者加分，**打4分，必须经过大家一起讨论**
* **标签**：3分不需要打标签以及备注，0，1，2，4分都需要用对应的标签进行标注，同时写明备注
* **备注**：对0，1，2，错误的地方进行**总结写上错误的地方，**4分需要写哪里比较优质

# 三、提效手段
“智慧图问” 的评测需求主要源于多模、一言等业务场景，其核心挑战体现在多个维度：评测任务量庞大（每周需处理 300 + case）、时效性要求严苛（需在 3 天内完成）、场景类型丰富（涵盖 10 多种题型），且评测难度高 —— 不仅完全依赖主观判断，部分案例（如数学解题、代码类）还对专业性有极高要求，甚至单个长文本案例的评测就需耗时 0.5 天。这种高强度、高复杂度的评测工作耗费大量人力，因此，迫切需要引入大语言模型（LLM），从工程化落地与评测能力升级两个层面实现效率提升。

# 主题四：基于VLM的自动驾驶场景理解与评估——宋泽良
# 一、业务背景
### 1.1 自动驾驶范式
        目前萝卜的自动驾驶方案遵循”感知-预测-规划”范式，由感知模块对多路相机和传感器输入进行编码，输出动静态障碍物，以及感知语义信号（OCC，施工区域、异常路面、死车语义等），预测模块接收感知信号对动静态障碍物预测多模态未来轨迹以及决策，规划模块根据障碍物轨迹、感知语义、定位信号对主车未来轨迹进行规划，最后转成控制信号（方向、油门）。

![死车](https://rte.weiyun.baidu.com/wiki/attach/image/api/imageDownloadAddress?attachId=85812f7eee8a4bbb8c1480e68390cb16&docGuid=melDGNhz9L7p5L "死车")
![施工区域](https://rte.weiyun.baidu.com/wiki/attach/image/api/imageDownloadAddress?attachId=0b305e11b1504a9cbd620e707cd4041f&docGuid=melDGNhz9L7p5L "施工区域")
### 1.2 VLM嵌入方式
       当前的链路比较依赖感知信号检出质量和范围，无法应对路上困难场景或者是长尾场景，因此引入了VLM模块来解决此类问题。为了方便迭代，不与现有模块耦合，目前VLM在自动驾驶系统中以外挂的形式嵌入，接收多模态输入（包括多路相机图像、场景 prompt），输出场景理解结果。

![VLM嵌入方式](https://rte.weiyun.baidu.com/wiki/attach/image/api/imageDownloadAddress?attachId=721cbe1845c44bd7bbe1a33adc1177de&docGuid=ofyvGUVSuKmbFo "VLM嵌入方式")
### 1.3 场景理解业务方向
        目前VLM主要应用在绕行语义、施工事故区域、异常路面、脱困轨迹等场景理解业务方向。

        绕行语义：需要对行进路径附近的车辆进行判断是否需要绕行，例如对于违停死车需要绕行，对于排队车辆需要不绕行。

        异常路面、事故区域：需要对前方道路情况进行理解, 是否存在交通事故或者异常路面（积水路面、塌陷路面），对于异常道路需要进行rerouting。

        施工区域：主要针对感知施工区域信号存在漏检和误检进行兜底判断。

# 二、多模态理解
### 2.1 技术方案
        由于VLM模型容量和推理时延限制，目前VLM通过在车端Trigger和实时融合，云端推理的方式进行工作。VLM接收camera 环视相机作为视觉模态，通过VIT进行token化、以及Lidar处理后的BEV结构化信息，导航指令，任务描述等组装成文本prompt作为语言模态，经过LLM输出CoT思考过程，meta action，宏观决策，施工事故区域理解，轨迹阻塞理解，以及形式轨迹等信息。车端利用小模型对云端响应结果进行融合，提升输出频率。

### 2.2 多模态训练范式
        考虑到现有的开源VLM偏向一些通用的图像理解任务，对自动驾驶场景下的特定知识匮乏，目前方案是先post-pretrain一个通用的自动驾驶语言模型，即对于自动驾驶场景和对应的交互方式有较好的理解能力，再基于该能力对指定的任务进行SFT，并由此得到最终的任务网络。示意图如下：

### 2.3 **Post-Pretrain**
**        该阶段目标是让其具备通用的自动驾驶理解能力，因此，可行的训练方式是是收集所有自动驾驶相关任务集合，集成为一个大的pretrain数据集合，同时启动多种预训练任务，让模型具备自动驾驶通识**，基于此，对预训练任务的定义如下：

* **输入：**
    * camera数据，包括单帧图片，多帧图片等；
    * 上游感知结果（地图，障碍物，信号灯等，文本化）；
    * prompt；

* **输出：**
    * 场景及任务描述，包括天气，时间，驾驶场景等；
    * 环境感知及理解，包括道路环境、车道条件**、**场景环境描述、路灯属性等；
    * 行为理解能力，包括障碍车行为（预测）及主车行为（规划），对行为的理解可以拆解成meta action和trajectory；
    * 特殊场景的理解，如交警指挥，施工，事故等；

* **数据来源：**
    * 各类通用图片理解相关数据集合，包括：RefCOCO，Object365，Crowdhuman，GQA，ScienceQA等；
    * 各类自动驾驶QA数据集合，包括：NuScenes-QA，DriveMLLM，MAPLM，DRAMA等；
    * 内部自建数据集合，包括：建图，感知，PNC等数据集合以及通过GPT+模版转化集合等；

* **开源数据集目前支持的功能：**

    1. Scene Understanding
    2. Vision Grounding
    3. Road Understanding
    4. Motion Prediction
    5. Trajectory Planning
    6. Driving Suggestion

* **输出方式：**结合下游需求以特定格式输出，类似下游需要json格式输出，在预训练阶段可以构造一批类似的输出来保持这种能力；

# 三、多模态评估
### 3.1 多模态评估指标
    1. 传统测评指标
        1. Accuracy，F1 Score，mean Average Precision (mAP)
        2. 优点：大部分指标都只能反馈预测和答案的精确匹配性能
        3. 缺点：忽略了语意一致性问题，可能存在很多假阳性(同义词问题)，无法消除模型训练数据偏差的影响

    2. 新测评指标
        1. CircularEval:该指标用于抵消一些模型对特定数据的偏见，要求模型在多次随机环形问答中，都能输出正确答案，以确保对内容理解的正确性


![](https://rte.weiyun.baidu.com/wiki/attach/image/api/imageDownloadAddress?attachId=34b0fea16bdd4e778012e8a55be4beb0&docGuid=WfeQgcT8gOYYaX "")
        2. GPT Score：给定任务定义和评价标准，利用大模型评估输出结果的得分。

            * 案例：自动驾驶垂类领域CoT自动标注数据增强预训练，在DriveBench上感知、预测、规划等VQA任务上GPT score相比原始VLM模型提升显著。
