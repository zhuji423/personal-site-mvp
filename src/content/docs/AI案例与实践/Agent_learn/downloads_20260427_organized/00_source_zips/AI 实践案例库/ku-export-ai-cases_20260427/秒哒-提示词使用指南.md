秒哒-提示词使用指南

#### 🧑‍🏫 案例作者：[@彭谷琪](https://ku.baidu-int.com?t=mention&mt=contact&id=422c2e80-f2cb-11f0-80f0-91056ee5134c)
#### 🎬 案例分类：需求
#### 🔧 使用工具：秒哒
#### 📒 案例概要：本文介绍了秒哒提示词的撰写技巧，如何描述需求，可以让秒哒更容易生成更符合你的需求的产品
## 使用指南
### 写清第一条描述
当大家说 “改进一下” 时，每个人心里的想法可能都不一样。所以在调整前，或许可以先试着想一想：哪里需要改、打算怎么改、为什么要这么改 —— 把这些小思路理一理，后续方向会更清晰～



**一个小自检问题**

> “把这个任务给一位不在这个领域的朋友，他能立刻明白要做什么吗？”
> 要是 TA 暂时没 get 到，或许咱们可以把描述再细化一点，让需求更易懂


### 第一个描述为什么重要
比如想做一个食谱应用，与其只说 “做一个食谱应用”，不如咱们先让需求更具体：

* 是否有主页？主要信息与入口是什么？
* 是否需要登录/注册？支持哪些方式？
* 有仪表盘吗？展示哪些指标/列表？
* 用户是否可添加内容？流程与校验规则如何？
* 风格关键词（清爽/活泼/温暖/极简…）与主色调？

当然，**您可以选择把所有需求都写得很详细** —— 这样模型能更贴近你的想法；**也可以只把重要需求说清楚，剩下的细节交给模型**～有时候给它一点发挥空间，说不定会有超出预期的小惊喜。



### 即取即用的秒哒指令模板
想拿到更贴合期待的输出？这几个小要点或许能帮到你：

1. 补充上下文——说明动机、约束与受众，并给出原因以便模型泛化（**“应用将在做菜时使用，需离线可用与语音播报；用户常单手操作，请提供大按钮与逐步计时提示”优于“做移动端适配”）**
2. 把需求写清写具体，写明**应用里包含哪些功能模块，怎么使用**，如果你希望节省思考的时间，可以写的不用过于复杂，只挑选重要的需求进行详细描述，否则现有的模型能力难以将您的需求全部实现。
3. 光有功能还不够，加点视觉和交互描述会更棒。比如**您可以适当加一些视觉和交互方式的描述**，如视觉设计的字体/配色/动效，如交互设计的交互逻辑/界面布局（如果您对设计的专业术语不熟悉，也可以上传您中意的参考界面截图，作为模型的设计参考）。
4. 如果有不希望模型做的内容，也可以明确说出来：**比如 “不要用鲜艳的颜色”“不要做分享功能”**，这样模型能更聚焦你想要的方向。
5. 要是想知道生成的应用好不好用，**我们有 “测试工程师” 子 Agent 模块专门负责测试。**你可以说说希望验证哪些目标，比如 “要能正常打开使用”“核心功能没 bug”。
6. 如果你有更高的期待，**比如 “支持按食材筛选食谱”“给 3 种首页布局方案参考”，**也可以直接写出来，让输出更有亮点。



示例模板：

```
【目标】……（一句话说明用途）
【受众/场景】……（谁来用、在何处看/听/用）
【功能模块】……（应用里包含哪些功能模块，怎么使用）
【交互与视觉设计】……（字体/配色/动效/参考图; 交互逻辑/界面布局）
【约束】（可选）……（不使用X；时长/字数/色盲友好等）
【评估标准】（可选）……（可验证：KPI、可运行、覆盖用例）
【超越基础】（可选）……（多方案并列、权衡与取舍、异常与边界）
```


**示例 1 ：**

> *【目标】​**
> **打造以作品为核心的极简展示主页，凸显 “少即是多”，方便访客浏览作品、了解摄影师及约拍 / 联系。​**
> **【受众 / 场景】​**
> **受众：摄影爱好者、潜在约拍客户、合作方​**
> **场景：桌面端 / 移动端浏览，用于作品欣赏、约拍咨询、商业合作​**
> **【功能模块】​**
> **顶部导航栏：含 “作品”“关于”“约拍”“联系” 文字入口，点击跳转，滚动时文字变色​**
> **作品分类筛选：“人像”“风光”“纪实”“商业” 标签（细线分隔），点击选中显 1px 横线​**
> **作品展示区：大留白网格（单作品占 70% 视觉空间），hover 显细灰标题框（名 + 拍摄地）​**
> **关于板块：左极简肖像（纯色背景），右核心理念 + 关键履历（仅文字展示）​**
> **底部区域：细体签名、微信 / Instagram 图标、邮箱，点击图标 / 邮箱可跳转 / 唤起邮件​**
> **【交互与视觉设计】​**
> **视觉​**
> **背景：纯白 / 浅灰 / 纯黑（三选一，无纹理渐变）​**
> **字体：无衬线黑体（如思源黑体），仅字号区分​**
> **色彩：仅黑白灰，线条用细直线​**
> **布局：大留白，作品无边框，关于板块左 3 右 7​**
> **交互​**
> **加载：全页淡入（0.5-1 秒）​**
> **作品切换：淡入淡出（0.3-0.5 秒）​**
> **导航适配：桌面显文字，移动端折叠为三横线汉堡标*

**示例 2：**

> *【目标】开发霓虹灯赛博风的贪心算法科普互动网页，通过游戏 + 科普结合，让用户完成 “操作→疑惑→深入理解” 的贪心算法学习闭环。**
> **【受众 / 场景】受众为贪心算法初学者（如学生、编程入门者）；场景为电脑、手机等设备上的网页端浏览与互动。**
> **【功能模块】**
> **顶部导航模块：固定显示 4 个标签（游戏 / 算法是什么 / 生活应用 / 算法对比），点击标签无刷新切换内容，手机端缩为 “≡” 图标，点击弹出标签列表；**
> **游戏模块（首页）：7×7 迷宫，玩家用方向键或屏幕按钮控制绿色方块角色，按 “选离终点最近方向” 规则移动，右上角显示步数 / 耗时，右下角有 “重新开始” 按钮，通关弹出动画；**
> **科普模块（3 个标签页）：均含发光标题 + 扩展式内容，点击 “查看详情” 可展开 / 收起补充说明，分别介绍算法定义、生活应用、与其他算法对比；**
> **跳转模块：游戏底部提示、通关提示、算法对比页底部文字可点击跳转对应页面。**
> **【交互与视觉设计】**
> **配色：背景 #000000（科普页加淡灰网格 / 橙色星空点缀），主色霓虹橙 #FF7F50（当前标签、标题、边框等）、霓虹绿 #39FF14（提示、角色、起点）；**
> **字体：标题用艺术字体（契合赛博风），正文用无衬线默认字体；**
> **动效：标签切换 300ms 淡入、扩展内容 150ms 下滑、按钮 hover 0.2 秒边框发光、角色移动 0.1 秒放大、终点 1 秒闪烁；**
> **布局：固定导航栏 + 下方内容区（游戏区占屏幕 70% 居中，科普页卡片横向 3 列排版）；**
> **交互逻辑：游戏合规移动留绿光轨迹 / 步数 + 1，违规不移动并弹窗提示，死胡同退回上一步；“查看详情” 按钮点击切换内容展开 / 收起，交互新增界面用弹窗。**
> **【约束】使用原生 HTML/CSS/JS+Canvas，不依赖第三方框架；需响应式适配（手机 / 电脑）；界面交互新增内容不改变原有结构长宽。**
> **【评估标准】**
> **功能可运行：游戏移动规则生效（合规 / 违规 / 死胡同反馈正常），导航切换、内容展开 / 收起功能正常；**
> **体验达标：动效流畅无卡顿，手机端导航与游戏控制适配良好；**
> **覆盖核心需求：游戏陷阱体现贪心局限，科普内容覆盖算法定义、应用、对比。**
> **【超越基础】**
> **游戏设计：通过 “贪心陷阱路径” 与 “绕路正确路径” 直观对比，让用户亲身感受贪心算法 “短视性”；**
> **内容设计：科普案例结合导航、排日程等生活场景，降低理解门槛；**
> **体验优化：角色与终点发光效果、星空点缀强化赛博风记忆点，通关动画提升互动成就感。*
