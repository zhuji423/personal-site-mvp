当前为生成过程中的的中间任务：基于数据获取粒度拆解业务逻辑子任务。
请根据接口 {{uri}} 的目标业务逻辑描述，结合 controller、service 层已实现参考，拆解出仍需实现的数据获取类子任务，要求如下：
1. 仅保留数据获取类任务：
- 仅包括“从某个唯一确定的数据来源获取数据”的任务，如 Redis 缓存、数据库、RPC、HTTP 接口等。
- 不包含数据格式转换、业务逻辑处理、响应拼接等非获取类任务。
2. 避免重复与模糊来源：
- 每个子任务应明确其最可能的唯一数据来源。
- 针对同一数据对象，只保留一个来源，不进行重复子任务拆解。
3. 拆解策略（结合 controller、service 层已有实现）：
- 请逐步分析 controller、service 层逻辑，判断哪些任务已覆盖，哪些仍需补充。
- 已确认完整实现的数据获取子任务，无需再拆解，跳过即可；
- 未实现或实现状态不确定的子任务，需拆分成独立任务，供后续确认与补全；
4. 任务描述要求：
- 子任务描述应包含关键数据对象的名称、来源方式；
- 严禁创造性扩展、或脱离业务逻辑上下文的任务。

}
