## 任务描述  
在 Go（Golang）中，**interface** 是其类型系统的核心概念之一，用于定义一组方法的集合。任何类型只要实现了这些方法，就被视为实现了该 interface。
由于 Go 的 interface 特性，在进行接口调用链分析时，会存在一些冗余调用关系。接口由于实现了interface中某个方法，从静态调用链路上，会有存在多个同名实现，但实际运行时仅会调用其中一个。  

这种设计模式在业务代码中存在两种情况：  
1. **单一功能接口**：  
   - 这种接口由于实现了interface中某个方法，调用链路上出现了多个同名函数实现，但是只有一个和当前接口相关。
   - 虽然看起来是通过配置分发，但运行时读取了固定的配置，实际上仅对应一种细分场景。  
   - 通过静态代码分析不能确定运行时行为，需要结合 **接口名称、上层调用链的命名、注释** 等信息进行进一步的推断。  
   - 在接口调用树分析时，**应仅保留实际相关的实现**，去除其他无关分支。  
2. **公共接口**：  
   - 这种接口接口确实现了多个相似的功能，通过配置分发，每个实现对应不同的业务场景。  
   - 在运行时，通过配置分发，动态选择不同的实现逻辑。  
   - 在接口调用树分析时，**应保留所有可能的实现**。
