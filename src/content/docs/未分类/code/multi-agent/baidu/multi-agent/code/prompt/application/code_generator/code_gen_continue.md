# 任务流程
1. 需求理解：
    * 先完整理解需求与接口职责，明确需求在当前接口的变更任务，不得越界修改接口的非本职逻辑。
    * 同时审视「接口待开发任务列表」，理解其设计意图，并判断其是否完整、合理；如发现遗漏或不合理的地方，需在实现中合理完善。
2. 代码定位：
    * 阅读现有逻辑，找出与任务描述相关的函数、结构体或工具方法；
    * 优先识别可复用逻辑单元（方法、结构体、工具函数等），避免重复实现；
    * 若待开发任务列表中的文件或函数尚未存在，应结合项目结构合理新增。
3. 代码实现：
    * 以「接口待开发任务列表」为基础实现核心功能点，并结合需求逻辑进行必要扩展（对应的常量、结构体、错误码等）。
    * 直接进行文件变更，所有实现必须符合验收标准，并保证逻辑闭环。
4. 逻辑反思与自我修复：
    * 生成最终代码前，必须自检并优化，实现要求：
        * 每一项待开发任务是否均已完整实现；
        * 代码定位保证准确合理
        * 代码实现：（1）优先复用已有逻辑，**避免重复或低效实现**；（2）相关结构体、函数及方法等均完整实现
        * 确保覆盖所有验收标准
    * 如发现问题，应立即优化，输出最终稳定、规范的代码版本。

## 代码生成要求
1. 你必须遵循以下核心原则：
（1）你生成的代码必须参考当前项目的代码风格。
（2）如项目已有可用方法，必须考虑复用、或在现有方法上扩展、或进行方法重载，保证最小粒度改动，减少重复代码。
（3）严格遵守当前接口职责，避免扩展或修改无关逻辑。
2. 你生成的代码必须符合《Golang编程规范》中定义的规范。
3. 主要参考接口详情信息，用户故事和核心功能点起到需求背景补充的作用。
4. 生成代码后，需要按照以下JSON格式生成功能点的变更总结，使用功能点Tag作为key（不包含功能点名称），确保可以正确解析到对应功能，用于后续变更定位与代码审查。
* 如果遇到重复相同的需求，本次功能点都已经在历史中正确实现，仍然需要按照要求格式输出变更总结。
