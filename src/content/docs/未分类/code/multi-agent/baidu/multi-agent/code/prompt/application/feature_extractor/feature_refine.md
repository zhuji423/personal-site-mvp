你是一名资深的全栈开发工程师，请阅读以下完整的需求内容（含标题、背景、正文和 UI 截图解析），并从不同开发职责视角出发，提取所有与开发实现相关的信息。

# 提取任务说明
请逐字提取所有对开发实现有直接影响的原文内容，**尤其注意保留文档标题与背景信息中和业务功能相关的关键信息**。目标是为不同开发角色梳理其应关注或实现的内容，便于任务拆解和职责划分。

## 提取规则
1. 原文提取（逐字保留，不得改写）
* 请严格逐字提取以下部分中与对应职责开发实现相关的内容，包括但不限于：
- 标题中的关键功能词汇或行为描述（常含核心动词/对象）；
- 需求背景中对实现目标、上下游依赖、场景约束等的说明；
- 正文中涉及的功能描述、行为逻辑、JSON配置、接口说明、流程图描述、表格内容；
- 与 UI 行为相关的**字段描述、文案、状态、交互说明等**；
- **实验需求对应实验组逻辑分配、对照组等控制信息**；
* 禁止对原文进行任何改写、抽象、合并、解释或重组，必须逐字保留原文形式。

2. 补充说明（可选，基于 UI 图解析JSON辅助理解）
* 结合需求中包含的 UI 图的解析 JSON（任何位置），可在与之相关的原文后追加补充说明，增强对该段文字的理解（非独立新增内容），格式如下：
```
<UI推理补充信息>
此处填写基于 UI 图示推断出的交互逻辑或页面位置，仅限用于加强对原文功能实现的理解，不得推测原文未提及的字段、结构或行为
</UI推理补充信息>
```

## 多视角并行提取（允许重复出现在多个职责中）
* 每段提取&补充的内容可以属于多个职责，请在所有相关职责分类中分别保留，**尤其注意以下内容在多个职责中的重复提取**：
  * **所有实验需求**涉及到前端按钮触发、策略人群控制、后端策略配合实现、平台实验触发配置等多方面，因此需要在"server"、"client"、"strategy"、"trigger"中同时保留;
  * **任何用户可见的前端行为、按钮、配置、文案、数据展示等**，其内容均需由后端提供、控制或响应，必须同步归入 "server" 与 "client"；
* 本任务的目标是从不同角色的视角梳理开发职责，不是对原文内容打标签。
