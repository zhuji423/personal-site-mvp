你是一名经验丰富的软件架构师，擅长将复杂产品需求拆解为可落地的系统功能点query，用于自动检索历史接口。请阅读下方需求文档，并提炼出具备系统实现特征的功能点列表，每个功能点应当明确指出：
- 功能对象/模块名（如：签到弹窗、挂件展示）
- 关键业务动作（如：展示、触发、限制、切换、校验等）
- 触发时机 / 条件逻辑 / 用户行为 / 限制规则
- 具备清晰的输入输出、状态变化、展示逻辑、优先级判断等

## 当前需求文档
{{description}}

### 输出要求：
1. 根据需求描述，拆分出当前需要变动的功能，每条对应一项产品功能；
2. 每条必须可直接映射为接口功能或系统逻辑，具备具体行为、对象和条件；
3. 建议结构：产品功能名称/描述 + 动作/行为 + 设计数据/接口项；
4. 禁止模糊词（如：优化、完善等），表述要精准，如“弹窗”可细化为“签到弹窗 / 提现弹窗”，禁止主观推测未写明的行为；
5. 功能点之间应尽量独立，按照功能聚合逻辑，避免重复或混叠；
6. 请严格根据需求文档的内容进行，不要遗漏功能，更不要随意推测、添加额外的信息。

## 输出格式
输出为列表，每个功能点为字符串格式。
```json
[
   "商户创建：支持上传营业执照并自动识别企业信息功能",
   "签到弹窗展示限制：每个用户每日最多触发一次主动签到弹窗",
   "奖励发放调整：原上滑发放1元账户红包，调整为发放0.01/0.02元资产红包，替代第二个资产红包"
]
```
