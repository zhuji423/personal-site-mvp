# 代码生成任务流程
1. 需求理解：
    * 首先理解当前需求与待开发功能，梳理出当前用户指定功能点的实现设计。
    * 检查「待开发功能点」，理解其设计意图，并判断其是否完整、合理；如发现遗漏或不合理的地方，需在实现设计中合理完善。
    * 功能点设计完成后，开始进行代码生成任务。
2. 代码定位：
    * .rules/目录下包含当前代码库的总体框架结构和编码规范，
        - 请先查看代码库总体框架结构信息辅助定位文件；
        - 然后根据当前需求，查看可能相关的编码规范
    * 根据用户编写的功能实现设计，定位到可能与当前功能相关的函数、结构体或工具方法，确定需要修改的内容；
    * 识别可复用逻辑单元（方法、结构体、工具函数等），避免重复实现；
    * 若设计文档中指定文件或函数尚未存在，应结合项目结构合理新增。
3. 代码实现：
    * 以「功能点设计」为基础实现核心功能，并结合需求逻辑进行必要扩展（对应的常量、结构体、错误码等）。
    * 实现设计中可能指定涉及修改的文件、函数，以及需要使用的MCP工具，遵循代码设计中的描述信息进行开发。
    * 实现要求：
        （1）生成的代码必须参考当前项目的代码架构、编码风格，必须符合对应编程语言的规范（如Golang、Python、C++等）；
        （2）所有改动避免影响其他已有字段、逻辑的使用；
        （3）保证代码规范性、可读性、可维护性、最小改动原则；
        （4）不要修改原文件的换行符格式。        
4. 逻辑反思与自我修复：
    * 生成最终代码前，必须自检并优化, 确保代码满足了实现要求；
        * 每一项待开发任务均已完整实现；
        * 严格遵守当前模块设计，不得越界改动中未涉及的逻辑。
    * 如发现问题，应立即优化，输出最终稳定、规范的代码版本。
5. 变更总结：
    * 代码生成完毕后，务必使用 code-change-summary skill 生成本次功能点的代码变更内容总结，用于后续变更定位与代码审查。
