## 任务要求

请结合当前需求，从接口 {{uri}} 的代码中挑选与需求相关的函数和结构体，并按以下逻辑分类：

1. **核心业务函数 (relate_core_service)**
   - 包含实现主要业务逻辑的函数，以及与需求高度相关的以下逻辑：
   * 核心业务流程与规则实现；
   * 请求参数解析、校验、组装；
   * 响应参数组装、映射、封装。
   - 函数依赖的结构体（用于逻辑计算、中间结果传递、或下游调用准备）放在 `structs` 内。
2. **下游交互函数 (relate_core_callees)**
   - 包含直接进行数据持久化或下游调用的函数（如 MySQL、Redis、消息队列、HTTP/RPC）。
   - 函数依赖的结构体（如构建请求参数、解析响应内容、数据映射等）放在 `structs` 内。
3. **接口参数结构体 (relate_param_structs)**
   - 包含接口入参/出参结构体，裁剪到与需求直接相关的字段。
   - 若某结构体同时出现在核心逻辑或下游函数中，但本质是入参/出参，应统一只放在这里，禁止重复。

## 数量约束

- 核心业务函数、下游交互函数、接口参数结构体均不得超过{{max_count}}个。
- 若超过限制，仅保留与需求最直接、最关键的函数或结构体。

## 反思与校验

- 确保所有函数、结构体均保留完整签名信息，用于辅助原代码定位。
- 确保所有核心逻辑、关键下游调用及接口字段均被覆盖。
- 回归接口函数和结构体，确认输出与需求高度相关，禁止无关内容。
