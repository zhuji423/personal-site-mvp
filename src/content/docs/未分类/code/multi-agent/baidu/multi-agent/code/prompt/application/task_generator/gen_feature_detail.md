# 任务目标

把输入的需求文档整体视为**一个功能点**，基于需求原文、验收标准及业务语义进行分析。
**判定该功能点中需求内容在不同代码库之间的承接归属**，明确 “需求原文的哪些内容由哪个代码库直接负责实现”，
为后续分层设计与研发任务拆解提供明确、可复用的职责判定依据。

# 输出约束

- `linkedRepos` ：表示该功能点中，**需求原文的哪些内容由目标代码库负责承接与实现**，至少输出一个代码库
- `linkedRepos.todoContent`：存放代码库承接的需求原文
    - 若仅涉及一个目标代码库
        - **直接承接完整需求原文即可**
        - **不拆分、不改写**
    - 若涉及多个代码库：按代码库职责，**对需求原文进行承接拆分**
        - **必须可直接映射回需求原文中的具体段落或要点**
        - 不得新增、推断或补充需求

# 输出格式

- 严格遵守以下JSON输出格式，**禁止输出额外解释**：
- **注意字符串内引用使用单引号**，避免 JSON 无法解析

```json
{
    "featureName": "功能点名称",
    "featureDesc": "功能点概述（<=30字）",
    "linkedStories": ["挂载的需求点标签，示例：需求点1"],
    "acceptanceCriteria": [,
      // 用户故事对应验收标准，严格遵守EARS 格式
      "[序号]. 当 [事件] 发生时，系统应当 [响应]",
      "[序号]. 如果 [前置条件] 成立，系统应当 [响应]",
      "..."
    ],
    "linkedRepos": [
        {
            "iCodePath": "目标代码库完整路径，示例：baidu/jady/ug-duoduo-video",
            "todoContent": "string, 承接的需求原文"
        }
    ]
}
```
