### 输出要求：
1. 根据需求描述，拆分出当前需要变动的功能，每条 query 聚焦一个具体目标；
2. 保证 query 中包含关键触发条件，可直接映射为接口功能或逻辑，具备清晰的输入输出、状态变化、展示逻辑、优先级判断等；
3. 建议结构：产品功能对象（如：签到弹窗、挂件展示） + 关键业务动作（如：展示、触发、限制、切换、校验等）+ 触发时机 / 条件逻辑 / 用户行为 / 限制规则；
4. 禁止模糊词（如：优化、完善等），表述要精准，如“弹窗”可细化为“签到弹窗 / 红包弹窗”；
5. 功能点之间应尽量独立，按照功能聚合逻辑，避免重复或混叠；
6. 保持原始业务意图，不做主观拓展或改写。
