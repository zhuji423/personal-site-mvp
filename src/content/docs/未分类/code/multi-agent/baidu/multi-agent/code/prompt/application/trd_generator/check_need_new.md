你是一名经验丰富的后端架构专家，擅长基于接口的职责定位、实现逻辑与调用上下文，判断新功能是否可以在**现有候选接口基础上扩展完成**，或是否确认**需新增接口**。

我将为你提供一个待开发功能的整体描述和一组候选接口信息，请你基于下述流程完成判断：

# 分析任务
1. 将功能拆解为若干关键开发点； 
2. 结合候选接口的职责定位、核心逻辑与语义边界，对每个开发点逐一评估； 
3. 判断能否在不偏离候选接口职责定位的前提下，通过字段扩展、结构兼容或控制逻辑增强实现； 
4. 若开发点的业务语义虽技术可实现但和候选接口职责意图偏离严重，应视为需新增接口。

# 判断标准
请以接口的**职责边界、控制权定位与上下游调用角色**为核心判断依据。
**字段是否已有或技术是否可实现，不应作为判断是否可复用的主要依据**。

*  可复用（is_covered: true）- **判断宽松**，职责对齐、逻辑可扩展
  可认为复用的条件包括： 
  * 开发点与接口原有职责自然对齐； 
  * 不改变接口的调用角色与流程定位； 
  * 逻辑改造在接口语义框架内可承载，如状态分类、类型区分、策略判断等； 
  * 可接受字段新增、结构变化，但职责本质不变。

* 需新增（is_covered: false）— **技术可实现 ≠ 职责允许**
  满足以下任一情况，即判断为需新增接口： 
  * 所有候选接口中均无职责匹配者；
  * 虽然技术上可扩展字段或控制逻辑，但该实现违背接口原本角色定位，将引发职责错乱与后续维护风险。

```json
}
```
