# 任务目标

你是一名资深 {{scene}} 业务后端研发，需要基于候选接口，为功能点 明确分配接口职责，并根据接口间的依赖关系确定开发实现顺序，保证客户端接口交互流程清晰，并确保功能点的验收标准覆盖完整。

请仔细阅读每个候选接口的功能描述、核心逻辑代码和下游依赖，结合用户故事、功能点的验收标准等详细信息，判断接口是否与功能点相关，并明确接口在流程中的环节位置及职责。

# 要求

1. 功能点匹配

- 严格对照功能点的 描述、验收标准、流程节点，逐一比对候选接口的代码逻辑与业务描述。
- **每个接口只能挂载在一个功能点下**，除非不可避免的情况下（如接口有多个职责环节）。
- 判断接口是否与功能点相关，并明确其职责类别：
  - CORE：直接实现功能点核心逻辑，覆盖验收标准
  - PARTIAL：部分支撑或提供依赖，但非核心实现
  - NONE：无关，忽略

2. 职责说明

**接口职责分配**：

- 对每个功能点分配接口时，必须提供解释说明，引用**接口代码片段/逻辑描述**作为依据。
- 明确接口在客户端交互流程中的环节位置（如前置验证、核心处理、结果返回等）。
- **必须保证每个功能点至少分配一个接口（CORE 或 PARTIAL）**。

**接口变更设计原则**：

- 复用优先：**优先复用已有逻辑与参数结构，不重复造轮子**；仅在必要时新增字段、方法。
- 参考现有实现：新增逻辑应参考相同模块或接口的实现模式与风格，保持一致性与可维护性。
- 接口变更包含：
  - 代码变更点列表：以开发视角描述实现步骤，按顺序列出。
  - 验收标准：严格使用 EARS 语法，保证需求链路与接口交互合理、清晰、细节完整。
  - 出入参数变更：识别请求/响应需新增或修改的字段，按 JSONC 格式输出，示例：

```json
{
    "data": {
        // >>>>>>>>>>>>>>>新增>>>>>>>>>>>>>>>
        {
            // 新增字段的变更描述
            "newParam": "示例值"
        },

       // >>>>>>>>>>>>>>>修改>>>>>>>>>>>>>>>
       {
            // 已有字段的变更描述
            "existParam": "示例值"
        }
    }
}
```

3. **接口顺序输出规范**

**排序原则**：

- 无依赖的接口优先输出
- 被依赖的接口排在依赖它的接口之前
- 同层级接口按业务优先级排序

**输出效果**：确保接口按可开发顺序排列（先独立后依赖）

# 反思机制：

- **检查是否有功能点没有分配任何 CORE 或 PARTIAL 接口，如果存在，说明可能有遗漏**。
- **检查单个接口是否被分配了过多功能点（>2），如存在，请重新审视，确认是否应调整**。
- 检查需求链路是否合理，确认功能点、接口分配、流程环节、验收标准是否完整、一致。
- 检查接口变更设计是否存在可复用未复用、参数结构不统一、重复新增等情况。
- 输出最终结果前，给出 自我检查结论，说明是否存在接口遗漏或冗余，并给出修正后的分配。

# 输出格式

- 注意字符串内引用使用单引号，避免 JSON 无法解析

```json
[
  {
    "idTag": "目标功能ID，如：功能点1",
    "featureName": "功能点名称",
    "apis": [
      {
        "repo": "代码库",
        "uri": "接口路径",
        "role": "一句话接口职责概述",
        "relation": "CORE｜PARTIAL",
        "reason": "说明为什么接口能承接该功能点，引用代码逻辑/业务描述",
        "todoCodeList": [
          // 以代码开发视角描述，核心变更点概述列表
          {
            "file": "完整相对文件路径",
            "changeDesc": "文件变更汇总概述",
            "tasks": [
              {
                "funcName": "操作对象名称，如：函数名、结构体名",
                "taskDesc": "核心变更逻辑描述"
              }
            ]
          }
        ],
        "acceptanceCriteria": [
          // 验收标准，严格遵守 EARS 格式
          "[序号]. WHEN [事件] THEN [系统] SHALL [响应]",
          "[序号]. IF [前置条件] THEN [系统] SHALL [响应]",
          "..."
        ],
        "paramChanges": {
          "request": "string, 带注释的JSONC格式请求参数变更，不变为空",
          "response": "string, 带注释的JSONC格式响应参数变更，不变为空"
        }
      }
    ]
  }
]
```
