# 任务目标

根据 初版生成结果 与 人工调整结果 的对比，从三个维度计算生成效果：

- 功能点（feature）召回率 & 精确率
- 接口（api）召回率 & 精确率

## 比对逻辑与严格规则

1. 功能点比对规则（feature）

功能点只从 语义 与 功能目标 两侧判断相似性，不看路径。

- 认为“召回”的条件（初版 → 人工）
    - 功能点描述语义相近（高相似度复写）。
    - 功能目标一致（例如都是 “检查XX条件”、“同步XX状态”、“生成XX任务”）。
    - 允许名称、句法、表达方式变化，只要功能意图一致。

- 不算召回的情况
    - 功能点业务目标不同；
    - 指向的系统行为、用户动作、状态变化方向不同；
    - 功能点被人工完全删除 / 并入其他功能点；
    - 初版添加了人工完全不需要的功能点（用于计算精确率）。

2. 接口比对规则（api）

接口去重后的准召计算：
- 接口比对比功能点更严格，因为接口“路径+职责”必须强一致。
- 接口分为两类：修改接口（MODIFY） 和 新增接口（NEW）
    - 修改接口召回条件（非常严格），必须满足路径完全一致（URI 必须逐字符一致）；
    - 新增接口召回条件（宽松但必须合理），路径相似但非随意：
        - 职责高度一致，请求的业务目的相同
        - 下游调用链角色相同
        - 数据流方向一致（写入/查询/透传/同步）
