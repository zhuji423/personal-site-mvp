# 分析 4 大业务索引（增量更新）

## 任务 1：识别业务场景（增量）

识别线索（以有接口的业务场景为例）：
* 目录结构（如 src/user/, internal/task/）
* 路由前缀（如 /api/v1/user）
* Handler / Service 命名（如 UserService）

输出要求（增量）
* 对新增场景 → 生成完整新段落
* 对已有场景但有变更 → 仅更新对应项
* 对删除场景 → 从最终输出中移除
* 对容易与其它场景混淆的部分 → 必须填写差异说明

格式保持不变：
```markdown
## 1. 业务场景归类

### 场景：<场景名称>
| 接口名称 | 接口路径 | 功能描述 | 代码入口 | 所属文件 |
|---------|---------|---------|---------|---------|
| ... |
---

> 差异说明（当与其他场景相似时必填）：
> - 相似场景：...
> - 差异点：...
> - 核心中英文关键词：...
```

## 任务 2：识别通用能力（增量）

同步或新增以下信息：
* 存储对象（数据库/缓存等）
* 下游服务（RPC、消息队列、第三方 API等）

格式保持不变：
```markdown
## 2. 通用能力归类

### 2.1 公共存储对象
| 存储对象名称 | 类型 | 所在文件 | 描述 | 典型操作 |
|------------|------|---------|------|---------|

### 2.2 下游服务
| 服务名称 | 服务类型 | 调用接口 | 描述 | 调用方式 |
|---------|---------|---------|------|---------|
```

## 任务 3：场景与能力映射（增量）

增量规则：
* 仅修改受变更影响的行，不得全量重写
* 移除已不存在的能力引用
* 增加新出现的存储或下游服务引用

格式保持不变：
```markdown
## 3. 场景与能力映射

| 场景名称 | 涉及接口 | 存储对象 | 下游服务 |
|---------|---------|---------|---------|
```

## 任务 4：梳理交互时序（增量更新）

以有接口的业务场景为例：

仅对发生变更的接口更新调用链。

格式保持不变：
```markdown
## 4. 接口交互时序

### 场景：<场景名称>
[接口调用名称]
客户端 -> <接口路径>
       -> <Service方法>
          -> <存储对象操作>
          -> <下游服务调用>
       <- 返回 <输出参数>
```

# 总体输出规则（保持一致）

* 只输出定位锚点，不输出具体代码
* 精度为目录级，比如 services/user/
* 相似场景必须写差异说明
* 结构化表格 + 时序链路
* 完整但不冗余——未变化部分保持原样，不重写
