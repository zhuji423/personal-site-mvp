请你阅读以下需求描述，结合示例风格，对**功能 Server 开发所需承担的职责进行结构化澄清与拆解**，输出职责对应的澄清后的需求内容。

# 任务目标
围绕 Server 端实现职责，逐功能点完成如下澄清拆解：
1. **完整识别并还原每个功能点中的触发机制**
   * **必须覆盖所有状态条件、行为前提、时间节点、展示时机等关键逻辑判断**； 
   * **禁止省略、缩写或抽象原始描述中的任何关键词、限制条件或判断语句**；
   * 如有表格、枚举、嵌套条件、例外情况等，需**完整保留并逐条展开说明**。
2. 对每个功能点，从 Server 实现视角，严格按处理链路梳理关键逻辑要素，包括但不限于：
   * 参数的解析与校验，若存在明确必填参数需说明（只提取校验参数本身，逻辑判断另行拆分）；
   * **触发条件及判断逻辑**（明确指出所有触发、排除条件、时间节点、状态判断等关键判定点）； 
   * 依赖的外部信息源（如配置平台、策略服务、下游接口等）； 
   * 服务端核心处理流程（状态判定、内容决策、行为记录、接口下发等核心流程细节）； 
   * 对应接口字段及下发内容（文案、跳转链接、样式控制字段、状态标识等），保证与需求原文完全一致。
3. 将功能点**按合理维度归类整理**（如：任务类型、实验分流等），**避免无意义的重复拆分或割裂理解**。

# 输出要求
* **完整保留原始表述中涉及的提示语、行为触发条件、适用范围、时间节点、任务状态描述等关键细节信息**，**禁止简化或抽象**；
* 在原始需求意图基础上进行理解，**禁止扩展、禁止主观臆测、禁止在当前环节进行英文字段命名**；
* 输出结构应清晰分点，内容闭环，便于后续评审与接口实现拆解直接使用；
* 禁止输出任何总结、解释或模型理解类描述，仅还原需求中的实现职责。
