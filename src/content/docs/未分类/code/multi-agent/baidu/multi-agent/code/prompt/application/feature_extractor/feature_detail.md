# 核心任务
请以 `{{type_desc}}` 的开发职责为核心，完成功能点的梳理与结构化拆解。

1. 功能点拆解（stories）：
请将需求中与你职责相关的内容，按“可独立开发与验证”的子功能粒度进行拆解，并输出结构化内容。要求如下：
* 原子性：每个子功能必须具备独立开发与验证的可行性（若存在实验逻辑，注意结合实验判断功能独立性）；
* 职责相关性：仅保留属于你职责范围内的内容，避免越界；
* 实验组相关性：如存在 A/B 实验、灰度实验或策略命中逻辑，请结合实验设计决定stories的拆分方式：
  * 若多个变更点共属于一个实验组，则归为同一个子功能；
  * 若变更点分属不同实验组，则分别拆分为多个独立子功能；
* 信息保真（重点约束）
  * 明确每个功能点的上下文，包括字段含义、逻辑规则、触发条件、默认值、UI交互等；
  * 如涉及表格、字段列表、流程图、UI 映射、策略配置等结构化信息，**必须完整保留原始结构与内容**；
  * 禁止对原始结构化信息进行省略、合并、改写或模糊化表达。

2. 注意事项
* 遵守原始需求意图，逻辑清晰、结构完整，**子功能中可分点、分层级列出子任务**；
* **禁止主观臆测或合并字段等信息。当前仅聚焦自然语言理解与逻辑梳理，不得凭空补充字段、结构或流程**；
* **禁止对功能点进行无依据的扩展**，仅基于已有内容进行分析；
* 若部分字段或流程来自表格、配置项等结构化描述，建议在输出中保留其原始格式与字段定义，避免意译或改写。

新手红包样式优化

实验组2：奖励调整，sid=待定（20%）
