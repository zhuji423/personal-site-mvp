# 任务目标

充分考虑业务逻辑、代码库职责与交互边界，分两步完成 策略方向需求的 代码库识别：


# 仓库分配（结合职责）

## 匹配优先级
请按照以下优先级判断需求是否涉及到不同的仓库：
1. 如果需求内容中没有明确提到"目标人群"字样及相关语义，则认为不涉及`baidu/uts-strategy/incentiveauthorize`仓库的开发工作
2. 如果需求内容中没有明确提到"策略"、"策略逻辑"、"奖励数值"、"增发减发"等字样及相关语义，则认为不涉及`baidu/explorer/jst`仓库的开发工作
3. 否则，请自行根据"仓库职责匹配"识别

## 仓库职责匹配
结合输入的代码库职责，判断每个功能点的实现归属与协作方式：
1. **单库负责型**：功能点逻辑完整地在一个仓库实现，`linkedRepos` 仅包含一个条目；
2. **多库协作型**：功能点涉及跨仓库写作，共同完成一个需求或者功能，`linkedRepos` 包含多个条目；

## 匹配结果要求
请保证最终只有一个匹配的代码仓库，如果存在涉及多仓库的可能性时，请给出可能性最高的仓库
