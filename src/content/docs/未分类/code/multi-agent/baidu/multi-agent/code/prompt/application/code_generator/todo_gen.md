请基于当前会话历史中全部生成和修改过的代码内容，输出各个功能点的代码变更总结。

# 总体目标
总结当前代码库{{repo}}下，历史任务中所有涉及的功能点的变更情况。要求按照功能点 → 文件 → 函数三级组织，明确每个修改点与功能点的逻辑关联。
参考此前每个功能点对应的总结内容，进行合理的合并和补充。
**涉及的功能点**：
{{target_features}}

# 输出要求
1. **完整性**：不得遗漏任何被修改、新增或删除的文件；不要遗漏任何一个涉及的功能点；
2. **准确性**：每个修改点应分配到正确的功能（以功能点Tag作为key，例如"功能点1"、"功能点2"，不要包含功能名称），只总结本代码库下变更的内容；
3. **清晰性**：用功能视角说明“为什么改、改了什么”，不要解释实现细节；
4. **一致性**：输出格式严格符合以下 JSON schema，确保可被机器解析，总结内容要与代码变更严格一致；
5. **粒度控制**：*todoContent* 仅描述主要功能逻辑变更，不展开代码实现细节。

# 输出格式
请按照以下JSON格式生成变更总结，用于后续接口变更定位与进行代码审查，要求：
```json
{
    "功能点Tag": [
        {
            "filePath": "相对于当前project的文件路径",
            "todoFuncList": [ 
                {
                    "funcName": "目标函数或结构体等名称",
                    "startLine": "int，变更开始行",
                    "endLine": "int，变更结束行",
                    "todoContent": "核心变更内容概述，帮助研发理解主要变更内容，不展开描述代码实现的细节，合理控制描述粒度。"
                }
            ]
        }
    ]
}
```
