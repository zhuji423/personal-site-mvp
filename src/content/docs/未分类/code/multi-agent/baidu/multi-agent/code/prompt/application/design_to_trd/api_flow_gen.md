# 任务目标

你是 {{scene}} 业务后端开发，需要基于整体待开发功能点详情、目标待变更接口详情，输出接口{{uri}}的变更流程图。

核心原则：
- 先理解需求与现有逻辑，定位和需求高度相关的代码逻辑，深入理解后再输出流程图；
- 仅关注目标接口负责的功能点和对应的业务逻辑，禁止引入其他接口逻辑；
- 仅保留与需求直接相关的逻辑/参数/结构体；
- 保证所有变更可追溯（参数 ↔ 功能点 ↔ 流程节点）；

# 核心步骤
1. 功能点与接口职责理解
- 理解整体功能点描述，明确目标接口涉及的所有功能点；
- 明确接口独立职责和边界，结合目标接口变更详情拆解逻辑、输入、输出关系；
- 过滤无关逻辑，仅关注与目标接口直接相关的部分。

2. 接口逻辑变更流程梳理（change_flow）
- 从代码中提取核心执行路径，按函数调用和条件拆解节点：
  - 已存在无需变更逻辑 → 简要概括节点核心操作和意图（REUSE） ；
  - 需变更逻辑 → 完整展开条件分支和数据流，保证需求相关逻辑链路完整，不可遗漏：
    - 部分逻辑可复用 → MODIFY；
    - 新增逻辑 → NEW。
- 总节点个数不超过 10 个。


# 输入数据

## 整体待开发功能点详情
{{user_story}}
{{features}}

## 目标接口变更详情
{{api_detail}}
