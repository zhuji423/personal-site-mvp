# 游戏中心功能 Server - 交互角色背景知识
## 功能 Server
服务端核心处理模块，负责： 
* 接收客户端请求，解析用户信息与页面参数； 
* 根据需求进行实验逻辑判断与流程控制； 
* 按需调用 AMIS 平台、GCP 平台或外部服务获取配置/策略； 
* 汇总配置、实验结果与策略数据，组装并返回结构化响应。

## 交互系统职责边界
### 交互对象
* **客户端** 
  * 发起请求（包含用户标识、页面参数等）； 
  * 根据服务端返回的结构化数据渲染页面与更新状态； 
  * 页面内动态交互行为（点击、滑动、动画等）完全由前端处理，与服务端无关。
* **AMIS配置平台**：提供游戏中心不同游戏的页面配置字段信息，通常通过接口读取Redis/DB等数据返回至配置平台进行展示和配置。
   * 职责定位：**页面展示配置**；
   * 注意：**游戏字段配置全集需以现有代码实现和参数定义为准**，以下内容仅作参考，帮助理解常见配置类型，包括但不限于：
      * 基础信息：游戏ID、游戏标识、游戏名称、跳转地址、认证类型、收益类型、在线状态、认证状态、动画开关等；
      * 展示信息：游戏标签、游戏icon、游戏图片、海报、图标、脚标等；
      * 大厅排序：游戏排序ID、展示位置、排序权重等；
      * 标签信息：标签名称、边框颜色、背景色、排序权重等；
   * 边界要求：仅负责**静态/半静态展示字段，不涉及实验逻辑或个性化策略**。
* **GCP配置平台**：负责提供游戏中心任务及实验相关的参数配置，通过读取 GCP 平台的 JSON 构建响应结构体返回，包括但不限于：
   * 职责定位：**任务与实验配置**；
   * * 提供游戏中心任务、实验相关参数，通过 JSON 结构构建响应； 
   * 配置信息包括但不限于： 
     * 基础信息：任务/实验名称、唯一标识、分类、实验 SID 等； 
     * 个性化策略下发：根据用户信息返回奖励策略、抽奖策略等； 
   * 边界要求： 
     * 若无实验需求，不返回实验字段； 
     * 涉及实验时，需返回实验命中与策略分发结果； 
     * **仅负责实验/策略逻辑，不涉及页面展示配置**。
* **外部服务**：其他需求明确提到的游戏逻辑无关的外部服务接口，按需调用。

### 边界约束
* 原则：仅在需求明确涉及相关内容时引入平台，**禁止不明确或错误引入**
* 规则： 
  * 页面展示相关 → 使用 AMIS 
  * 任务/实验/个性化策略相关 → 使用 GCP 
  * 页面展示与实验/策略同时涉及 → 两个平台都使用 
  * 不涉及展示或实验/策略 → 不引入任何平台
